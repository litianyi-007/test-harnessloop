# 转向：停写契约，做竖切（2026-07-28）

> **两个独立视角同判，契约优先这条路走到头了。**

## 1. 两路证据收敛

| | 五面确认（同模型五实例） | T-079（grok，异构） |
|---|---|---|

| structural | **10** → 判据再次触发 | REWORK（作为权威文本） |

**S3 对 X10 的判词最锋利**：即便造出标注注册表，「它检查的是作者的自我声明彼此相符，
**从不检查声明与代码实际读了什么相符**」——**自签问题在更高一层复现**。

## 2. 根问题（T-079 的表述，我采信）

> 根问题不是「少一个 X10」，而是：**试图用纯函数 + 自签树 + 纸面标注，模拟一个跨时间、
> 对抗性的验收 oracle。**

**这个项目的核心纪律就是「拆掉实现，哪条断言会红」——而我在整条契约线上一次都没用过它。**

## 4. 新做法（采 T-079 的处方）

1. **冻结语义**：用户裁决 A 已足够。**停止扩写元规则。**
   - **X10 降级**为非-teeth 的审查清单。
   - **§0 根规则降级**为**构造约束**（判定链只允许两象限调用），**不再声称 validate 可判定**。
2. **一条竖切 > 五面契约**。最小可跑集：
   - **S3 子集**：`<goal>/evals.json`（`eval_id` / `activation_round` / due 规则）
   - **S2 子集**：`acceptance-evals.json`（`eval_id` / `attempt_id` / `outcome` / `frozen_due_set`）
   - **S4 子集**：`decision.md` 的 `Acceptance evals:` + **一条硬规则**：
     **「本轮 due 的 eval 在账本里缺 ran ⇒ 不得 positive」**
   - 接进既有 `verify_protocol.py` 与 coverage
   - **teeth = 破坏性 fixture**，不是标注一致性
3. **硬度若要升级，换权力来源，不换纸面**：宿主强制跑门、或探针 runner 出具
   **非 agent 可写**的 receipt。**不再发明第四个「捕获点」。**
4. **方法**：综合规格前必须有**可红的 fixture**；连续类级洞 → 停写契约，先竖切。
5. **措辞**：对外称 **「收盘时序门 + 轮内自洽账本」**；「硬门」仅在加限定
   （写入当轮、协议时序）时使用。**T-079 判：不加限定即过度声称。**

## 5. 五面产出里仍然有用的东西（不作废）

- **68 个冻结字段清单**（五面各自产出）——竖切的直接输入。
- **252 条判定的时间层分类**——哪些能进轮层、哪些只能是今天层，已逐条标好。
- 五面各自的 schema 与 kind 清单——竖切扩面时的现成材料。

**契约 v1–v5 的价值在于它证明了什么走不通，以及产出了这三样可用材料**，
不在于它本身能当权威。
