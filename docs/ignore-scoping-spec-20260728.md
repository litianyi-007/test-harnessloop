# `verify:ignore` 收窄 — 规格 v2（2026-07-28）

> **v2 是对 v1 的重写，起因 T-071 对抗审判 REWORK。**
> v1（commit `d5de1e3`）提出的 `verify:ignore=<span>` 精确语法**已整体撤回**，理由见 §2。
> v1 全文在 git 历史里，不在此复述。
>
> 状态：**规格草案，待第 2 轮对抗审**。实现未开始，机械门仍在 v0.25.0。
> 前置关系：本规格是 **B2b 的硬前置**。

## 1. 要解决的两个问题（不变）

来自真实评审 pilot（`docs/rule-ab-pilot-report-20260728.md` §5.1）：

**(a) marker 作用域是整行，会连带豁免同行的无关引用。** 实测：为豁免 1 条散文引用，
同行另 1 条完全正常的引用（`gateway/config.py:2005-2014`）一并停检，无任何信号。

**(b) `citations_ignored_explicit` 数的是 code span 不是引用，高估 2.3×–5.3×。**
一份既有评审字段报 5、实际豁免引用 0。**用来看清 (a) 有多严重的那把尺子本身不准。**

## 2. v1 的精确语法为什么被撤回

v1 提议 `<!-- verify:ignore=<span>[,<span>] -->`。T-071 逐条证伪，其中一条是决定性的：

- **`,` 做分隔符不可解析，而反例就在本协议自己身上。** 引用可以带多区间 locator：
  `foo.py:10-20,30-40`。这不是构造出来的边角情形，是 `LINE_SUFFIX_RE` 明确支持、
  语料里实际存在的写法。没有 escaping/quoting 语法就无法无歧义还原原 span——
  **而引入 escaping 语法，成本已经超过它要解决的问题**。
- `-->` 出现在 span 文本里的处置，v1 完全没规定，等于把关键行为留给实现去猜。
- **反向误命中**：按文本比较会命中同一 cleaned text 的**全部** occurrence，
  而不是作者心里的那一个。同行重复引用时静默多豁免——v1 想解决的问题原样重现。
- v1 的 `citations_ignored_collateral` 定义与自己举的例子矛盾（"单引用 + 裸 marker"
  一处算 0、按定义应算 1），不存在同时满足两者的实现。
- v1 的"零迁移"漏了 coverage schema：(b) 的口径修正会让历史 `decision.md` 里逐字
  记录的数值与重跑结果对不上。

**撤回是对的。** 为 1 条已观测的 collateral 引入一套尚未闭合的字符串协议，
代价与风险规模不成比例。

## 3. v2 的核心：一个不变量，不是一套语法

> **一个 marker 至多豁免一条引用。**

这个不变量由**目标行的引用条数**机械保证，不需要任何新语法：

### 3.1 作用域

| marker 形式 | 目标行 |
|---|---|
| **独占一行**（该行除 marker 外无其它非空白内容） | **下一行** |
| **行内**（marker 与内容同行） | **该行自身** |

两种形式都保留。v1 与 T-071 反提案都只保留独占行形式，**那会打断 markdown 表格**——
表格里插入一个独立注释行会终止表格。而表格行恰是引用密集处。实测语料：多引用行共
144 行，其中表格行 12 行（8%）——比例不高，但足以让"只允许独占行"变成一条会逼人
破坏文档结构的规则。

### 3.2 目标行必须恰好有 1 条引用候选

| 目标行引用数 | 结果 |
|---|---|
| 1 | 豁免该条。**这是唯一的正常情形** |
| 0 | 违规 `ignore-marker-stale` |
| ≥ 2 | 违规 `ignore-scope-ambiguous` |

**`0` 也判违规**，因为陈旧 marker 是当前形式的一个静默失效模式：引用被修好或删掉后，
marker 留在原地，继续豁免**此后落到那一行的任何东西**。实测既有语料里就有这种
marker——它一条引用都没豁免，却被字段计成豁免了 5 条。

**≥2 的处置不是新语法，是拆行**：把那一句拆成两行（markdown 段落内的换行是软换行，
渲染不变），或者对确实不该被反引号括起来的散文路径去掉反引号。多引用行里 92% 不在
表格中，拆行直接可用；余下表格行需要重排单元格，属已知摩擦，见 §7。

### 3.3 occurrence 歧义由此消失

T-071 指出 v1 的文本比较无法表达"同一行同一文本出现两次、只豁免第一次"。
v2 里这个问题**不存在**：目标行只允许有 1 条引用候选，多于 1 条直接违规。
不变量把整类歧义关在门外，而不是去解析它。

## 4. 历史豁免：按文件摘要，不按时间

严格规则会让**现有语料变红**——实测 7 个既有 marker 里只有 1 个满足 §3.2
（2 个目标行有 2/3 条引用、其余目标行 0 条）。而历史评审产物**不得为了让机械门通过
而修改**（v0.12.0 E1）。所以必须有豁免机制。

`.harnessloop/setup/ignore-legacy.json`（版本化、可 diff）：

```json
{"version": 1, "legacy": [{"path": "<项目内相对路径>", "sha256": "<该文件当前内容摘要>"}]}
```

- 列表内且**摘要匹配**的文件：沿用旧的行粒度语义，不报 §3.2 的两个新 kind。
- 列表内但**摘要不匹配**（文件被改过）：**按严格规则处理**，并报
  `ignore-legacy-digest-mismatch`。
- 不在列表内的任何文件：严格规则。

**为什么按文件摘要而不是按 round 或协议版本号**（T-071 建议的是后者）：
按 round 豁免会留一个洞——一个被标为 legacy 的 round 日后新增一份评审，
它也自动获得旧语义。按文件摘要是内容寻址的：它**只**豁免今天确实存在的那几份文件，
任何新文件在任何地方都拿严格规则。同时它天然自证——文件一旦被编辑就失去豁免，
这恰好是我们要的激励方向（E1 本就要求别改它们）。

**不用 mtime**，理由与 T-071 一致：时间戳不进 git、跨机器不可复现、可被 touch 篡改。

## 5. 计数口径修正

### 5.1 `citations_ignored_explicit` 只计真引用

先跑完整的 citation 判定，再对判定为引用者计数。**纯口径修正，被豁免的集合一条不变。**

### 5.2 新增 `citations_ignored_unscoped`

**定义**：被豁免的引用中，由**旧语义（行粒度）marker** 豁免的条数。

严格规则下一个 marker 至多豁免 1 条，故该字段等价于"来自 legacy 文件的豁免量"——
定义唯一、无自相矛盾，且正是 B2b 预登记要设阈的那个量（建议阈值 `== 0`，
即新评审不产生任何未受约束的豁免）。

v1 的 `citations_ignored_collateral` **撤回**：T-071 证明它的定义与举例互相矛盾、
且同时漏报和误报。

### 5.3 coverage schema 版本（T-071 第 5 项，v1 漏掉的）

口径修正会让历史 `decision.md` 里逐字记录的 coverage 数值与重跑结果对不上。
`--json` 输出与 coverage 行新增 `coverage_schema: <int>`，本次修正把它推到 `2`。

历史记录不改、不追认，**但从此可判读**：schema 1 的数字按 span 口径读，
schema 2 按引用口径读。不加这个字段，两个不同口径的数会被后来人当成同一件事对比。

## 6. 验收（teeth）

每条须有破坏性反证：拆掉实现，对应检查立即变红。

| # | 断言 | 破坏性反证 |
|---|---|---|
| J1 | 独占行 marker + 下一行恰 1 条引用 → 豁免该条；同一文件其它行引用照常被检查 | 扩大作用域到多行 → 红 |
| J2 | 行内 marker + 该行恰 1 条引用 → 豁免该条（表格行可用） | 取消行内形式 → 红 |
| J3 | 目标行 2 条引用 → `ignore-scope-ambiguous`，**两条都不被豁免**（不是豁免其一） | 退回行粒度 → 两条都被豁免 → 红 |
| J4 | 目标行 0 条引用 → `ignore-marker-stale` | 去掉 stale 检查 → 陈旧 marker 静默存活 → 红 |
| J5 | 计数口径：一行 10 个纯标识符 span + 1 条引用 + marker → `citations_ignored_explicit == 1` | 退回 `len(CODE_SPAN.findall(line))` → 报 11 → 红 |
| J6 | legacy 摘要匹配 → 旧语义、零新违规；**违规 kind 与 detail 逐字节不变** | 忽略 legacy 名单 → 既有语料变红 → 红 |
| J7 | legacy 文件被改一个字节 → `ignore-legacy-digest-mismatch` + 严格规则生效 | 只比路径不比摘要 → 篡改后仍享旧语义 → 红 |
| J8 | 不在 legacy 名单的新文件，即使放在 legacy round 目录内，也拿严格规则 | 按 round 豁免 → 红（这条焊死 §4 的选择） |
| J9 | `coverage_schema == 2` 出现在 `--json` 与 coverage 行 | 去掉字段 → 红 |
| J10 | `citations_ignored_unscoped`：legacy 文件里一个 marker 豁免 3 条 → 报 3；严格规则下任何 marker → 至多 1 | 字段恒 0 → 红 |
| J11 | 零迁移：全项目当前 **0 违规**，实现后仍 **0 违规**，coverage 除新增字段外逐字段不变 | 任何行为外溢 → 红 |

## 7. 已知摩擦（如实登记，不掩饰）

- **表格行有 ≥2 条引用且需要豁免时，无法靠拆行解决**，只能重排单元格或去掉某个反引号。
  语料里这种行至多 12 行，且其中真正需要豁免的是极少数。属**可接受但真实**的成本。
- **`ignore-marker-stale` 会让"写了但没用上"的 marker 变成硬错误。** 这是有意的
  （见 §3.2），但作者第一次遇到时会觉得突兀。错误 detail 必须写清目标行、
  该行找到 0 条引用、以及正确的两种作用域形式。
- **legacy 名单需要人工维护一次**（写入当前 4 份文件的摘要）。之后除非有人违反 E1
  去改历史评审，它不需要再动。

## 8. 显式不做

| 提案 | 理由 |
|---|---|
| `verify:ignore=<span>` 精确语法 | §2。可在**定义了可逆编码与 occurrence 作用域之后**重提，不是现在 |
| 通配 / 前缀 / 正则 | 等于把空白支票换个写法发出去 |
| 裸形式整体判违规 | 违反 E1（唯一迁移手段是改历史评审） |
| 按 round / 协议版本号做 legacy 分流 | §4：留下"legacy round 里新增文件自动获得旧语义"的洞 |
| 强制 marker 附非空理由 | 与本规格的两个问题正交，且给一个罕见操作再加摩擦。留作独立议题，不在此夹带 |
| 对 `citations_ignored_unscoped` 直接报违规 | 阈值应由 B2b 重新预登记决定，本规格只负责测准并暴露 |

## 9. 给第 2 轮对抗审的靶子

1. **§3.2 的"恰好 1 条"是否真的消灭了 occurrence 歧义**，还是把它推到了别处？
2. **§4 的摘要豁免**：摘要按什么口径算（原始字节？规范化后？行尾差异？跨平台？）——
   规格没写死，这是不是又一个"留给实现去猜"？
3. **§3.1 保留行内形式**是我在 T-071 反提案之上加的（理由是表格）。这个放宽是否
   重新打开了什么？行内 marker 的"该行自身"作用域，与独占行的"下一行"作用域，
   两者相邻时会不会重叠或互相遮蔽？
4. **J3 断言"2 条引用时两条都不豁免"**——这是我选的语义（fail-closed）。
   另一种选择是"报违规但仍按旧语义豁免"。哪个对？
5. **`ignore-marker-stale` 判违规是否过激**：一个不起作用的注释，值得让整个门变红吗？
6. **本规格是否仍然过度设计**。T-071 已经砍掉一轮。请独立判断：只做 §5（两个计数
   修正 + schema 版本）、完全不碰作用域，是否才是与风险规模相称的做法？
   这一问允许否决 §3 与 §4 的全部内容。
