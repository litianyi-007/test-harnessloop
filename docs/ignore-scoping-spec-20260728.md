# `verify:ignore` 收窄 — 规格（2026-07-28）

> 起因：真实评审 pilot 第 1 轮（`docs/rule-ab-pilot-report-20260728.md` §5.1）。
> 状态：**规格草案，待对抗审**。实现未开始，机械门仍在 v0.25.0。
> 前置关系：本规格是 **B2b 的硬前置**——在此之前 B2b 不解锁。

## 1. 问题陈述（两个，不是一个）

### (a) marker 的作用域是「整行」，会连带豁免无关引用

实现（`verify_protocol.py:689`）：

```python
if IGNORE_MARKER in line or (i > 0 and IGNORE_MARKER in lines[i - 1]):
    ignored_explicit += len(CODE_SPAN.findall(line))
    continue
```

marker 出现在本行或上一行 → **该行所有引用全部跳过存在性检查**。

pilot 实测：为豁免 1 条散文引用，同一行上另 1 条完全正常的引用
（`gateway/config.py:2005-2014`）一并停止被检查，**且无任何信号**。

### (b) `citations_ignored_explicit` 数的是 code span，不是引用——它在说谎

同一行代码里，计数用的是 `len(CODE_SPAN.findall(line))`：把 `` `model_routes` ``、
`` `:56` ``、`` `>=3.11,<3.14` `` 这类**根本不会成为引用**的 span 也计进去。

| 语料 | 字段报 | 真实被豁免的引用 | 倍数 |
|---|---|---|---|
| setup-wizard 三份既有评审 | 14 | 6 | 2.3× |
| pilot 的 2 个 marker | 21 | 4 | 5.3× |

一份既有评审字段报 **5**、实际豁免引用 **0**。

**(b) 比 (a) 更该先修**：这个字段存在的唯一理由就是让 ignore 的使用可监测；
**用来看清 (a) 有多严重的那把尺子本身不准**，且偏差方向不固定——既可能高估，
也可能把「豁免了一条要害引用」稀释在一堆无害 span 里看不出来。

## 2. 语料实测（决定取舍的依据，不靠直觉）

73 份真实评审、679 个含引用的行：

| 每行引用数 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 行数 | 537 | 89 | 35 | 9 | 6 | 3 |

- **79% 的含引用行只有 1 条引用** → 对这些行，行粒度与精确粒度**等价**，收窄对它们零影响。
- **21% 有 2 条以上**（p90=2，p99=5，max=6）→ 连带风险只存在于这 21%，且上界是 5 条。

**结论：(a) 的危害是真实的但有界的**。这否决了「推翻重做」，支持「加一个精确形式，
把不精确形式的代价变得可见」。

存量 marker：73 份评审里仅 **4 份含 marker、共 6 个**。迁移面极小——但见 §5，
历史评审产物**不得为迁移而改**。

## 3. 设计

延用本项目已验证过的那条判据（`nested_under` 嵌套裁决的同一形状）：
**不禁止不精确的用法，而是提供精确用法、并让不精确用法的代价成为可见事实。**

### 3.1 修 (b)：计数口径改为「引用」

`citations_ignored_explicit` 只计入**本来会进入 `cited` 的 span**，即先跑完整的
citation 判定（alias 形 / pattern / bare-domain / placeholder / out-of-project /
PATHISH 前缀 / 形状分支），再对判定为引用者计数。

**纯计数口径修正，不改变任何判定行为**：被豁免的集合一条不变，只是数得对了。

### 3.2 新增精确形式 `verify:ignore=<span>`

```
<!-- verify:ignore=hermes_agent.egg-info/ -->
<!-- verify:ignore=build/,hermes_agent.egg-info/ -->
```

- 作用域与裸形式相同（本行或下一行），但**只豁免文本完全等于所列 span 的引用**。
- 多个 span 用 `,` 分隔。**不支持任何通配/前缀/正则**——一旦支持，它就退化回一张
  空白支票，本规格的意义归零。这条是硬约束。
- 比较对象是**清洗后的 span 文本**（与 `cited` 里存放的同一形式：`strip()`、
  反斜杠转正斜杠），避免作者要去猜内部表示。

### 3.3 精确形式的名字必须命中：`ignore-span-unmatched`

若某个被点名的 span 在其作用域内**不存在**，报违规 `ignore-span-unmatched`。

这不是洁癖。当前裸 marker 的一个静默失效模式是：引用被修好或删掉之后，marker 留在
原地继续豁免**此后落到那一行的任何东西**。精确形式让「陈旧豁免」在下一次运行就红，
而不是变成一张长期有效的空白支票。

### 3.4 新增 coverage 字段 `citations_ignored_collateral`

计入：被豁免、但**不是任何精确 marker 点名**的引用条数。

- 一行只有 1 条引用 + 裸 marker → collateral 0（79% 的行落在这里）。
- 一行 3 条引用 + 裸 marker → collateral 3。
- 一行 3 条引用 + 精确 marker 点名其中 1 条 → collateral 0，另 2 条**照常被检查**。

这个字段是**本规格真正的产出**：它把 (a) 的代价从不可见变成一个可以进预算、可以设
阈值的数。B2b 的重新预登记应当直接对它设阈（建议 `== 0`，即新评审一律用精确形式）。

### 3.5 裸形式保留

裸 `<!-- verify:ignore -->` 继续合法、行为不变。理由是**硬约束而非偏好**：历史评审
产物不得为了让机械门通过而修改（v0.12.0 E1）。若把裸形式判为违规，唯一的迁移手段
就是去改 4 份历史评审——那正是 E1 禁止的动作。

裸形式的代价现在由 `citations_ignored_collateral` 记账。新评审用精确形式即可让该值
保持为 0，无需回头动任何历史文件。

### 3.6 显式不做

| 提案 | 不做的理由 |
|---|---|
| marker 只豁免「紧邻的下一条引用」 | 一行需豁免 2 条时无法表达（两个 marker 在不同行，作用域重叠且语义含混）。精确形式没有这个问题 |
| 通配 / 前缀 / 正则形式的 span | 见 §3.2：等于把空白支票换个写法发出去 |
| 裸形式判违规 | 违反 E1（见 §3.5） |
| 精确形式强制附非空理由 | 与本规格要解决的两个问题正交，且会给一个本就罕见的操作再加摩擦（pilot 里 7 份评审共 3 条豁免）。**留作后续独立议题**，不在本规格夹带 |
| 对 collateral 直接报违规 | collateral 的可接受阈值应由 B2b 的重新预登记决定，不由本规格预判。本规格只负责把它**测准**并暴露出来 |

## 4. 验收（teeth）

每条都须有破坏性反证：拆掉实现，对应检查立即变红。

| # | 断言 | 破坏性反证 |
|---|---|---|
| I1 | 一行 2 条引用 + 精确 marker 点名其中 1 条 → 被点名者豁免，**另一条仍报 dangling** | 把精确匹配退回行粒度 → 另一条被豁免 → 红 |
| I2 | 精确 marker 点名一个该行不存在的 span → `ignore-span-unmatched` | 去掉命中检查 → 陈旧 marker 静默通过 → 红 |
| I3 | 计数口径：一行含 10 个纯标识符 span + 1 条引用 + 裸 marker → `citations_ignored_explicit == 1` | 退回 `len(CODE_SPAN.findall(line))` → 报 11 → 红 |
| I4 | collateral：一行 3 条引用 + 裸 marker → `citations_ignored_collateral == 3`；换精确 marker 点名 1 条 → collateral 0 且另 2 条被检查 | 字段恒 0 → 红 |
| I5 | 零迁移：全部 4 份含裸 marker 的既有评审，违规 **kind 与 detail 逐字节不变** | 改动裸形式语义 → 红 |
| I6 | 无通配：精确 marker 里写 `*.md` / `build*` → **不**匹配任何 span（按字面比较），且因未命中报 `ignore-span-unmatched` | 引入任何模式匹配 → 红 |
| I7 | 作用域不越界：精确 marker 点名的 span 若只出现在**再下一行**，不被豁免且报 unmatched | 扩大作用域 → 红 |

## 5. 迁移与影响面

- **历史评审：零改动。** 4 份含裸 marker 的评审一字不动，I5 焊死这一点。
- **本项目当前状态：零违规不变。** `reviews/` 当前为空（pilot 已复原），
  setup-wizard 的 3 份评审在旧 goal 下、行为不变。
- **新增字段**：`citations_ignored_collateral` 进 coverage，须同步进 `decision.md`
  的 coverage 逐字记录纪律与 SKILL.md 文档。
- **B2b 预登记**：应对 `citations_ignored_collateral` 设阈（建议 `== 0`）。

3. **§3.4 的 collateral 定义**是否真的度量了「因行粒度而多豁免的量」，还是把某些
   本就该豁免的也算了进去？
4. **§3.5 保留裸形式**是否等于什么也没解决——如果新评审作者继续用裸形式，
   collateral 只是被记录而没有被阻止。这个"只测不拦"的选择对不对？
5. **I3 的计数口径修正**会不会让某个既有断言的语义悄悄改变（该字段已进过
   `decision.md` 的历史记录）？
