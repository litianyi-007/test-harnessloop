**pilot 不通过。** 不解锁 B2b。

- 预算 §2 的 5 个阈值中 **2 个不达标**（要求全部满足）。
- 预算 §3 的 4 个指标中 **2 个无法可信测量**、**1 个按有意义的口径不达标**。

### 阈值本身的标定问题（重要，但不据此改阈值）

预算 §2 的 zero-rate 与 p90 阈值，是拿 codex T-066 的代理语料数字做参照定的
（「声明外部基准后 zero-rate 18→34、p90 7」）。**那组数字是 2026-07-27 做的投影，
而不是对最终实现的测量**——它隐含假设「声明了外部基准，原本裸写的 `research/x.md`
就能解析」。而外部解析基准最终采用的是 **alias-only**：不写 `@@design/` 前缀就一律
不进外部域（这是 T-066 之后、经三轮对抗审确认的硬约束，规格 §2.4）。

**因此「声明外部基准」本身对原始负担的贡献恰好是 0**，每一条都必须逐条改写。实测
证实：声明 `@@design` 后立即复测，7 份评审的 dangling 数一条未变。

这不是阈值定得"太严"，而是**标定所依据的模型与最终实现不一致**。按预登记纪律，
本轮据此判不通过；正确的后续是**新开一份预登记**，用 alias-only 的真实成本模型
重新标定，而不是在这里把数字改到能过。

### 一条真阳性（值得单独记）

T-060 里字面写着 `` `.hopper/handoffs/T-055/T-057-output.md` ``——作者把「T-055 与
T-057 两份产物」写成了**一个从来不存在的合成路径**。这份评审当时是被接受的、
`decision.md` 已声明它为 `Review:` 对象，而这个错误一直没被发现。

**Rule B 抓到的是真缺陷，不是误报。** 这是本次 pilot 对「这道门是否买到了东西」最直接的一个正面答案。

### 两类只能靠 ignore 的引用

1. **时间性产物**：`kernels/hermes/build/`、`hermes_agent.egg-info/` ——评审当时确实
   存在（非 editable install 的产物），事后被清理。**Rule B 没有"当时存在"的概念**，
   改写无法解决。
2. **引用文件的内容而非路径**：评审在陈述"`.gitignore:59` 那一行的内容是
   `hermes_agent.egg-info/`"。被反引号括起来的是**一行文本的值**，不是一个路径引用。
   任何改写都不能让它不像路径。

这两类是否构成预算 §4 第 3 条一票否决（"某类引用在协议上无正确写法"），是一个判断题。
本报告判**不构成**：机械门文档明确把 `verify:ignore` 定位为"确属散文而非真实引用"的
设计内出口，这两类正落在该定位上。**但见 §五——这个出口本身有严重问题。**

## 五、预算未覆盖的两个维度（本 pilot 最重要的产出）

### 5.1 `verify:ignore`：连带压制真实存在，但**监测这件事的字段本身在说谎**

> **本节为 2026-07-28 更正版。** 初版把「被压制的引用」记为 21 条、连带 18 条（86%）。
> 那个数字直接取自 `citations_ignored_explicit`，而该字段数的是**该行所有 code span**，
> 不是「本来会成为引用的 span」。逐 span 复核后真实数字见下。初版结论（pilot 不通过）
> 不变，但连带压制的**严重性被高估了**，如实更正；同时这次复核挖出了一个更值得修的
> 缺陷——见 (b)。

**(a) 行粒度的连带压制：真实但规模远小于初报**

逐 span 复核我在 T-056 加的 2 个 marker：

| 行 | code span | 其中真正会成为引用 | 本意豁免 | **连带** |
|---|---|---|---|---|
| 48 | 6 | 2 | 2 | 0 |
| 73 | 15 | 2 | 1 | **1**（`gateway/config.py:2005-2014`） |
| 合计 | 21 | **4** | 3 | **1（25%）** |

连带压制是**真的**——第 73 行那条 `gateway/config.py:2005-2014` 是一条完全正常、
本该被检查的引用，因为同一行上有一个需要豁免的 span 而一起停止被检查，且无任何信号。
但比例是 25%，不是初报的 86%；绝对数是 1 条，不是 18 条。

风险随**同行 span 密度**放大：第 73 行有 15 个 span，是评审里典型的「一句话列举多处
源码锚点」写法。密度越高，一次豁免的连带面越大。

**(b) `citations_ignored_explicit` 高估 2.3×–5×——一个会误导的监测信号**

该字段存在的理由，是让 ignore 的使用「可监测而非静默」。但它数的是 code span：

| 语料 | 字段报 | 真实被豁免的引用 | 倍数 |
|---|---|---|---|
| 既有 setup-wizard 三份评审 | 14 | 6 | 2.3× |
| 本次 pilot 的 2 个 marker | 21 | 4 | 5.3× |

其中一份既有评审字段报 **5**、实际豁免的引用是 **0**——它的 marker 落在一行纯代码
标识符上（`` `model_routes` `` 之类），一条引用都没豁免，字段却显示"这份评审豁免了
5 条引用"。

**这比 (a) 更值得修**：(a) 是一个有边界、可估算的成本；(b) 是**用来看清 (a) 有多严重
的那把尺子本身不准**。B2b 之后若靠这个字段做 ignore 滥用监测，看到的数与实际脱节，
且脱节方向不固定（既可能高估也可能把"豁免了要害引用"混在一堆无害 span 里稀释掉）。

**方向（属规格层，见后续规格文档）**：
- 修 (b)：字段只计入**真正会进入 `cited` 的 span**——这是纯计数口径修正，不改判定行为。
- 修 (a)：把 marker 的作用域从「整行」收窄。可选形态包括只豁免紧邻的下一条引用、
  或 `verify:ignore=<确切字符串>` 显式指名、或对「一个 marker 豁免多于 N 条引用」
  报 coverage 警告。取舍见规格文档。

### 5.2 Rule A：7 个 round 里 6 个的 scope-lock 覆盖不到自己的 round 目录

评审入树后立刻冒出 6 条 `scope-lock-violation`。逐个核对 scope-lock 的 Allowed Changes：

| round | 声明的 round 目录 span | 能否覆盖 `reviews/` |
|---|---|---|
| 0001 | 无 | 否 |
| 0005 / 0006 | `.harnessloop/goals/.../rounds/000X/` — 字面量 `...` 是**占位符不是路径** | 否 |
| 0007 / 0008 / 0009 | `.harnessloop/rounds/000X/` — **少了 `goals/<goal-id>/`，该路径不存在** | 否 |
| 0010 | 完整正确路径 | **是** |

这些 scope-lock 一直被当作有效，因为 `reviews/` 一直是空的、Rule A 没有东西可查；
`evidence/` 在需要的地方是用完整正确路径单独声明的，恰好绕开了这个问题。

**Rule A 抓到的同样是真缺陷**：6 份 scope-lock 里写着解析不到任何真实目录的 span。
但它同时意味着 B2b 有一项预算完全没算过的成本——**每个 round 的 scope-lock 都必须
用完整正确路径声明自己的 round 目录**，而现有写法（省略中段、用 `...` 占位）自然会失败。

## 八、树的处置

pilot 是**测量**，入树是 B2b 的内容。故本次测量后：

- 7 份评审副本已从 `rounds/*/reviews/` 移除，各 round 恢复原状。
- `@@design` 外部基准声明（`.harnessloop/setup/reference-roots.json` 与本机绑定）
  **一并移除**。原因：本机之外没有绑定，声明会产生 `external-root-unavailable`
  + 每条 `@@` 引用一条 `external-citation-unverifiable`，让门在其它机器上直接红。
  这是设计上的 fail-closed（正确行为），但在没有任何 `@@` 引用留在树里的当下，
  留着它只有代价没有收益。B2b 时须连同**这项机器依赖性**一并重新评估并写进文档。
- 全树复测：`verify_protocol.py` **0 违规**，与 pilot 前一致。
