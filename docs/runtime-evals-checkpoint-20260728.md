## 2. 依据（§11.6 的定理）

> 门是**被守门方完全控制的树上的纯函数**；X9 又禁止用今天的声明去判已收盘轮。
> 二者合起来：对已收盘轮，门能读的一切都是被守门方在过去写下的自签数据。
> **因此「对已收盘轮的硬门」在结构上不可实现——它只能是记录。**

**三条独立的线收敛到同一边界**，这是接受它的主要理由：

| 线 | 结论 |
|---|---|
| 批 2（停止落痕） | 机械门能验证**结构关系**，不能验证**动机** |
| ignore 收窄 | 同层加检查无效，须**换层次** |

## 4. 「写入当轮硬门」由谁保证

**不由机械门区分轮次保证**——门是均匀的，对每一轮做同样的自洽核对。
「硬」由**协议的调用时机**保证：`Loop Continuation` step 1 要求在写 `decision.md` 之前
跑门且 exit 0（`loop/SKILL.md:551`），并把 exit code 与 coverage 行**逐字**记进
`Mechanical gate` 字段。

**因此性质是**：「一个被判 positive 的轮，在它收盘的那一刻通过了门」——
而不是「它今天重跑仍通过」。后者被 §11.6 证明不可得。

**残留（如实登记）**：有人可以不跑门就写 positive。这由既有的 `Mechanical gate` 字段
纪律承接——它是**记录**不是证明，这一点协议本来就写明了。本次不新增声称。
