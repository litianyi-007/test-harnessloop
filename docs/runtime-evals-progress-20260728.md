## 这一段的关键裁决（全部标注为主会话受托裁决，用户可推翻）

1. **激活是派生的，不是开关**（附录 E.2）——goal 从其 registry 声明 ≥1 条 eval 的那一轮起
   enforcing；`evals_declared==0` 合法可见；「干脆不声明」由 `thresholds.md` 的 Runtime 行反证。
   **锚点落在已存在、已被评审、删除即在 diff 里可见的散文表上**，不是新造的可删文件。
2. **C.3.2 改判**（附录 D）——原裁「不做全局 gate_blocking」造成了零违规总开关，
   改为 enforcing goal 的激活锚点必须「缺席即阻断」。
3. **批 2 采 (A)**（附录 E.1）——五条最小接线补丁后实现，其中最关键的是把 anomaly 消费
   机械化：`continue` 在未确认 anomaly > 0 时返回 `needs-human`。
4. **先裁极性、再钉载体**（接口契约 §1）——门永不读墙钟（S5）、今天的 registry 不得判红
   已收盘轮（S4）。极性冲突若不先解，任何载体设计都可能被整体推翻。

## 本段的方法论沉淀（已进 self-audit）

| 教训 | 触发 |
|---|---|
| **多面并行设计前必须先产出接口契约，且极性必须最先裁** | 三镜头判 does-not-compose，冲突 100% 在边界上 |
| **配对关系必须由数据自带的标识符建立，不得由顺序推断** | 我按 journal 顺序 zip 并发结果，5 面错配 4 面 |
| **三个窄镜头 > 一个大镜头** | 单 agent 拼五份设计做一致性检查因 prompt 过大 stall；三窄镜头全部完成且独立收敛同一结论 |
| **一个能被廉价满足的强制，只把成本加给诚实的人** | 批 2 v2 要求每个停止理由「有支撑」，支撑可被真实制造或自引用满足 |
| **收敛守卫的两种结局要分清** | ignore 收窄那次三轮指向「层次错」；批 2 这次三轮指向「方向对、接线未闭合」 |
