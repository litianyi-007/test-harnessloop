# 机械门横切约束 X1–X9（2026-07-28）

> **这份文件不提出新机制，它约束所有新机制。**
>
> 起因：批 1 五面设计的对抗批判产出 18 个 blocker、42 个 major，而**跨面看，它们大量
> 是同一批错误在五个不同面各犯一次**（`docs/batch1-design-synthesis-20260728.md` §2-3）。
> 逐面各修一次会得到五个互不一致的局部方案。
>
> **适用范围**：批 1 的五面（TH-0019/0020/0021/0022/0024）、批 2 的 v3.1（TH-0023），
> 以及此后任何新增的机械门判定面。
>
> **每条约束都由本项目真实踩过的坑生成**，并附一条 **meta-teeth**——即
> `harnessloop/scripts/validate.py` 里如何机械保证后续新面遵守它。没有 meta-teeth 的
> 约束只是劝告，而本项目已经证明过劝告会漂。
>
> 授权：main-session ruling under user delegation 2026-07-28。

---

## X1 锚点不可删：缺席即阻断，不得静默跳过

**病灶来源**：批 1 五面**全部**中招（综合 §2）。删掉 `goals/<g>/evals.json`、删掉激活
清单、所有 eval 行写 `system: null`、账本 `evidence` 留空数组——每一个都是**零违规的
全门旁路**，且比它们所仿的 reference-roots 先例更弱。批 2 v3 §5 的「无 `Profile:` 字段
则 anomaly 不报」是同族。

**约束**：

1. 一个判定面若可被「某文件不存在 / 某字段为 null / 某数组为空」整体关闭，
   **该状态必须是违规或至少是可见异常，不得是静默跳过**。
2. 判定面的**启用**不得由一个可自由拨动的 `enabled`/`activation_state` 字段决定。
   启用应当**从既有的、已被评审的事实派生**（附录 E.2 的做法：goal 的 registry 声明
   ≥1 条 eval 即 enforcing；而「干脆不声明」由 `thresholds.md` 的 Runtime 行反证）。
3. **例外必须显式论证**：reference-roots 的「缺席 ≡ 空列表 ≡ 今天的行为」是**合法**的，
   因为缺席意味着「本项目不读外部树」——一个**更小**的能力面。而 eval 面缺席意味着
   「硬门关闭」——一个**更大**的权限面。区分判据：**缺席让被检方获得更多自由 → 必须
   阻断；缺席让被检方获得更少能力 → 可以是零行为**。

**meta-teeth**：`validate.py` 对每个新增判定面断言：构造「锚点文件不存在」的 fixture，
断言产生违规或 anomaly 计数非零；破坏性反证 = 把该分支改回静默 `return`，检查必须变红。

## X2 路径身份：复用既有判据，禁止重新发明比较

**病灶来源**：**这是本项目第四、五次踩同一族**——v0.20（父目录逃逸）、v0.22（symlink
逃逸）、v0.25（大小写不敏感卷 `samefile`），批 1 的 S1（symlink 守卫只 `lstat` 叶子文件，
父目录逃逸不挡）与 S5（`is_under` 用 canonical 路径的**字符串前缀**，大小写不敏感卷上
可让 eval 静默消失）。**S5 的草案在否决备选时自己引用过这条理由，然后自己犯了。**

**约束**：任何涉及路径的判定**必须**调用既有实现，不得自写比较：

| 需要判断 | 必须用 |
|---|---|
| 规范化 | `_canonical`（`verify_protocol.py:438`） |
| 是否在项目内 | `_is_contained`（`:450`） |
| 是否在某个钉死的域内 | `_is_contained_pinned`（`:480`） |
| 两个路径是否同一目录 | `_same_dir`（`:1262`，`samefile`，**不是 `==`**） |
| 祖先/后代关系 | `_is_strict_descendant`（`:1285`，**不是字符串前缀**） |
| 存在性 + 类型 | `_exists_as`（`:1853`） |

**symlink 检查必须覆盖路径链，不只是叶子**：叶子 `lstat` 挡不住把父目录做成 symlink。
凡「该文件必须在项目内」的判定，一律以 `_canonical` + `_is_contained` 为准，
symlink 拒绝是**附加**检查而非替代。

**meta-teeth**：`validate.py` 对新面的源码做结构断言——涉及路径比较的函数中不得出现
裸 `==` 比较两个 `Path`、不得出现 `str(a).startswith(str(b))`。这是**形状断言**（较弱），
故**必须**同时有大小写不敏感卷与 symlink 父目录两个行为 fixture；形状断言只作为
case-sensitive CI 上的兜底（G24 的既有做法）。

## X3 解析纪律：文本外观 ≠ 解析结果

**病灶来源**：批 1 的 S2 与 S4 **各自独立**发现——JSON **重复键**与 **bool-as-int** 让
「人在 diff 里读到的值」与「门解析到的值」可以相反。`json.loads` 静默保留最后一个；
「未知顶层 key → 整份作废」是在**解析之后**对已坍缩的 dict 做的，抓不到。

**约束**：

1. **重复键即无效**：所有版本化 JSON 声明必须用 `object_pairs_hook` 检测重复键，
   命中即整份作废（沿用 all-or-nothing 纪律）。
2. **类型严格**：`true`/`false` 不得接受 `1`/`0`；整数不得接受数字字符串。
3. **未知键拒绝必须递归**，不能只查顶层——批 1 的 S2 明确指出「若未知 key 拒绝不是递归的，
   任何不在黑名单里的名字都是敞开的凭证通道」。
4. **闭合键集优先于黑名单**（见 X5）。

**meta-teeth**：每个新声明文件各一条 fixture——同名键出现两次、`"flag": 1`、
嵌套层出现未知键——三者均须整份作废；破坏性反证 = 去掉 `object_pairs_hook` / 放宽类型 /
只查顶层，各自变红。

## X4 teeth 必须断言规格要的性质，不是实现的当前形状

**病灶来源**：批 1 的 S3（`test-auth-domain-overbroad` 声称了一条**本项目协议已白纸黑字
判定为机械不可判**的性质，且实测可被一行正则架空；其 teeth 断言的是两个字面 fixture）；
S1（teeth #5「versioned 声明在构造上装不下 endpoint」**是假的**——`probe.path` 允许
`"//evil.example.com/api/status"`）。批 2 的 v1 更极端：**它的 L5 明文要求裸 `continued`
通过，等于用一条 teeth 保证了绕过存在**。

**约束**：

1. 每条 teeth 必须写出**破坏性反证**：拆掉实现的哪一部分会让它变红。**若拆掉实现它仍
   通过，它断言的不是实现承载的性质。**
2. teeth 不得断言规格**声称做不到**的事（自相矛盾），也不得断言比实现更强的性质。
3. 每条 teeth 应配一条**变异对照**：证明该输入在错误实现下确实失败（G24b 的既有做法）。

**meta-teeth**：这一条**不能**由 validate.py 自动保证——它是评审判据。故写入
`harnessloop-loop/SKILL.md` 的对抗评审提示，并作为每次规格对抗审的固定靶子
（本项目三次规格审均已实测有效：T-071/T-076/批 1 五面批判都是靠这一问抓到假 teeth）。

## X5 fail-closed 极性 + 白名单优于黑名单

**病灶来源**：批 1 的 S3——「生产底线做成了**黑名单**，且被两条路各绕开一次；
**极性也与本代码库的既定习惯相反**」。批 2 的 v2——`unjustified-stop` 判红是**反向**
过度（惩罚诚实标注者）。

**约束**：

1. 安全相关判定一律 **fail-closed**：不可判定时取「拒绝」而非「放行」。
   既有正例：`_same_dir` 的 `on_error=True`（「无法确认这两个不是同一目录」→ 按同一处理）。
2. 「允许什么」用**白名单**，不用「禁止什么」的黑名单。闭合键集、枚举值、操作类
   一律白名单。
3. **但 fail-closed 不等于「怀疑就判红」**：批 2 v3 的教训是——**一个能被廉价满足的
   强制，只把成本加给诚实的人**。若某性质机械上无法区分诚实与伪装，正确做法是
   **不强制、只记录并暴露**，而不是强制一个可被绕过的形式。

**meta-teeth**：新增枚举/键集的 fixture 必须含一条「枚举外的值」用例并断言拒绝；
新增安全判定必须含一条「判定所需信息不可得」用例并断言取拒绝分支。

## X6 未知枚举值必须 fail-closed（不得静默跳过整组检查）

**病灶来源**：批 1 的 S4 抓到一条**很险**的 fail-open：`Feedback` 规范化对未知取值
fail-open，**一个全角括号即可让全部 pass/fail↔positive 一致性硬门整体静默跳过**，
且不产生任何违规。

**主会话实测校准（一次自我更正，且把话说得更重）**：初稿写「本项目 decision.md 的
Feedback 值大量使用全角」——**不准确**，`Feedback` 与 `Review verdict` 两个字段在
14 轮语料里恰好是干净 ASCII。但同一批文件的**其它枚举字段几乎全部是「值 +（中文说明）」**：

| 字段 | 带全角括注 |
|---|---|
| `Human confirmation required` | **14/14** |
| `Scope-lock required` | **14/14** |
| `Safe without user input` | 11/14 |
| `Recovery eligible` | 11/14 |

实例：`- Human confirmation required: no（修复方向已由主会话拍板；……）`。

**所以风险比初稿说的更实**：这不是「可能有人这么写」，而是**本项目的既有写作习惯**——
任何对这些字段做精确枚举匹配的新判定，在 14/14 轮上都会命中未知值分支。fail-open 时
它们静默失效，fail-closed 时它们会把全部历史轮判红（这同时触发 X9）。正确解法是
**规范化后再匹配**（取全角括注前的值）**且**对规范化后仍未知的值判违规。

**约束**：从被检文件读取的枚举值，若不在已知取值集内，**必须产生违规**
（`<field>-unrecognized-value`），**绝不允许**「不认识 → 跳过依赖它的检查」。

**meta-teeth**：对每个从被检文件读枚举的判定，构造一条「值加了一个全角字符」的 fixture，
断言产生 unrecognized 违规而**不是**静默跳过；破坏性反证 = 改回 fail-open，
断言那组下游检查全部静默失效。

## X7 自由文本字段是凭证与路径的泄漏面（输入侧的 G20）

**病灶来源**：G20 纪律（violation detail / coverage / 默认 `--json` 不得泄漏本机绝对
路径）是**输出侧**的。批 1 的 S1 指出声明文件的自由文本字段（`purpose` /
`cleanup_contract` / `approved_by`）是**输入侧**的同一问题——它们会被读进违规 detail。

**约束**：版本化声明中的自由文本字段，加载期拒绝：`://`、`~/`、以 `/` 开头的绝对路径
片段。**诚实边界必须写明**：这挡不住「长得像参数名的密钥」，那一层归 TH-0025/EV-G 与
项目侧 `scripts/check-secrets.sh` 的 L1-digest，**规格不得假装挡住了它**。

**meta-teeth**：每个新声明文件一条 fixture——自由文本字段含 `https://…` 与 `~/x` 各一，
断言整份作废。

## X8 机械门永不发起网络请求

**病灶来源**：附录 C.1-A 原措辞「机制骨架（……每门重判 available……）可复用」会把实现者
带向让机械门发网络请求（批 1 的 S1 明确指出并要求修订，已在附录 D 改判）。

**约束**：`verify_protocol.py` **永不**发起网络请求、永不执行业务命令。它是**账本核对
器**，不是 test runner（附录 C 的 O-10 已裁定，此处升为横切约束）。runtime 的
available / pass / fail 由**探针执行器在探针时刻**判定并写进账本；门只核对账本。

**meta-teeth**：`validate.py` 对 `verify_protocol.py` 源码断言：不得 import
`socket`/`http`/`urllib`/`requests`/`ssl`，不得出现 `subprocess` 的新调用点（既有的
`git` 调用点白名单化并计数，新增即红）。

**前提已实测**（2026-07-28）：`verify_protocol.py` 的全部 import 为
`argparse`/`hashlib`/`json`/`os`/`re`/`subprocess`/`sys`/`pathlib`——**零网络模块**；
`subprocess` 的调用点全部是 `git`（`:1724`/`:1744`/`:1757`/`:1774` 一带）。
故该 meta-teeth 是**可立即实现**的，不是愿望。

## X9 追溯判红与 E1 的兼容规则

**病灶来源**：批 1 的 S4——「回填一条 due 条目会**追溯判红已收盘轮**，唯一出路是改历史
产物（撞 v0.12.0 E1）或删清单」。批 2 的 v1 也犯过（迁移的 E1 论证错误）。

**约束**：

1. 新判定面**不得**使已收盘且当时合规的轮次在今天重跑时判红。
2. 若某项修改在数学上必然影响历史轮，唯一合法处置是 **schema migration**：
   固定 cutoff（显式清单，不用 mtime）+ 迁移工具写入**唯一固定值** +
   **preimage 摘要**（迁移工具在写入前自算并落 manifest）+ 机械核对除该行外逐字节不变。
3. **不得**以「改历史产物」作为迁移手段——那是 v0.12.0 E1 明令禁止的。

**meta-teeth**：每个引入历史影响的新面必须有一条 fixture——在**未激活**的历史轮上运行，
断言违规集合与新面落地前**逐字节相同**。
