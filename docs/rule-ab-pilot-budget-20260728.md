# 真实评审 pilot — 预算预登记（2026-07-28）

> **本文件在任何测量发生之前写下并提交。** 之后的测量结果不得反过来修改本文件的
> 任何阈值；若阈值事后被认为定错了，正确做法是**记录它定错了、pilot 判不通过**，
> 然后另开一轮重新预登记——不是改数字让它通过。
>
> 这条纪律不是形式主义。本项目反复抓到的病灶就是「绿灯≠真守门」，而其中最难自查
> 的一种，是**先看到结果再决定什么算通过**。B2b 的后果是把 Rule A/B 升为全 round
> 硬要求，一旦定错，代价是每轮都吃一堵误报墙，并逼出「改被检文档转绿」的病理
> （v0.12.0 E1 纪律明令禁止的那件事）。

## 1. 语料与分层

**必须分两层测量、分别报数**（codex T-066 §2 的公平性要求）：

- **L-普通**：goal 002 的 10 个 round 中 `decision.md` 已声明 `Review:` 指向真实评审
  产物的 **7 份**（T-042 / T-047 / T-053 / T-054 / T-056 / T-057 / T-060），按其所属
  round 放进对应的 `rounds/<id>/reviews/`。这是 B2b 生效后每轮的真实形态。
- **L-自评**：评审「引用路径检查器自身」的元文档（T-058 / T-062 / T-063 / T-064 /
  T-065 / T-068 / T-069 / T-070）。它们天然含大量 fixture 路径、反例路径、不存在的
  攻击构造路径——**引用密度与不可解析率必然远高于普通评审**。

**两层不得互相污染**：不拿 L-自评 的长尾去否决 L-普通，也不拿 L-普通 的中位数去
掩盖 L-自评。L-自评 只报数、**不参与解锁判定**（它衡量的是检查器自己的语料特性，
不是普通轮次要付的成本）。

## 2. 解锁阈值（L-普通，全部满足才通过）

测量对象：把 7 份评审放进各自 round 的 `reviews/` 后，`verify_protocol.py` 报出的
`dangling-citation` 违规数，**按评审文档分组**。

| 指标 | 阈值 | 定这个数的理由 |
|---|---|---|
| **zero-rate** | **≥ 50%**（7 份里至少 4 份零违规） | 代理语料声明外部基准后是 34%。真实评审若连一半都做不到零违规，说明"多数轮次不需要人工处置"这个前提不成立 |
| **p50（中位数）** | **≤ 1** | 中位数超过 1 意味着典型轮次每次都要动手，这正是 B2 原本要防的"每轮吃一堵墙" |
| **p90** | **≤ 5** | 代理语料 p90=7。真实评审若长尾不比代理集更好，则声明外部基准这一步没有兑现它的承诺 |
| **max** | **≤ 10** | 任何单份评审超过 10 条，视为**机制的问题而非作者的问题**——该情形下必须记录成因，不得靠 ignore 抹平 |
| **非零文档均值** | **≤ 4.0** | 代理语料 4.8。要求真实评审优于代理集，否则"代理集偏悲观"这个假设不成立 |

## 3. 人工处置预算（L-普通）

| 指标 | 阈值 |
|---|---|
| 单份评审处置时间**中位数** | **≤ 5 分钟** |
| 单份评审处置时间 **p90** | **≤ 15 分钟** |
| `<!-- verify:ignore -->` 使用量**中位数** | **≤ 1 条/份** |
| `verify:ignore` 单份**上限** | **≤ 3 条**；任何一份超过 3 即判不通过 |

`verify:ignore` 的上限是硬的：**大量 ignore = 这道门什么也没买到**，只是把噪声换成
了噪声抑制器。若靠 ignore 才达标，等于用作弊换绿灯。

## 4. 一票否决项（任一触发即 pilot 不通过，与上述数字无关）

1. **改被检产物的实质内容来转绿。** 改引用路径的**写法**（`foo.md` → 正确的相对
   路径、或改写成 `@@alias/...`）是合法处置；改一条 finding 的**措辞、结论、证据
   引用对象**以躲开机械门，是 v0.12.0 E1 纪律明令禁止的行为，触发即否决。
2. **为了让某份评审通过而放宽机械门本身**（加豁免、加 fallback、放宽 containment）。
   pilot 期间机械门必须冻结在 v0.25.0，不得因测量结果而修改。
3. **发现某类引用在协议上无正确写法。** 即处置只能靠 ignore、无法靠改写解决——
   说明协议面还缺东西，应回到规格层而不是硬上 B2b。

## 5. 记录要求

pilot 报告须包含：分层原始数据（每份评审的违规数、处置耗时、ignore 用量）、
每一条被处置引用的**处置方式分类**（改相对路径 / 改 `@@` 外部引用 / 加 ignore /
其它）、以及逐条对照本文件阈值的通过与否。**不合格项必须显式写"不通过"**，不得
用"基本达标""接近阈值"之类措辞含混过去。
