# Thresholds

## Data Thresholds

| 项 | 阈值 | 不达标的处置 |
|---|---|---|
| submodule 与上游的距离 | **落后 0 个提交** | 落后即先 `git -C <submodule> pull --ff-only`，**不得在陈旧基线上动手**（2026-07-28 实测：落后 65 提交导致整版改动作废） |
| 缺陷来源 | 必须来自**真实使用** | 主动扫描出的问题可登记，但不计入本 goal 的轮次判据 |
| 凭证入库 | **0 处真凭证进版本库** | `check-secrets.sh --staged` 拦截即停；轮换后重跑 `--update-digests` |

## Verification Thresholds

| 项 | 阈值 | 说明 |
|---|---|---|
| 破坏性反证 | **每条修复至少 1 次，且先看到红** | 没红过的反证不算反证。红的实际输出须留存 |
| 主会话独立复跑 | **硬判据 100% 自己跑一遍** | 不采信实现方自述的测试结果 |
| 端到端判据 | **每条修复至少 1 条非单测证据** | 单元测试证明不了「东西真的送出去了」 |
| 安装产物复验 | **必须** | submodule 工作区跑通 ≠ 装上去的那份跑通 |
| 版本一致性 | **以各仓的发现式守卫为准** | 不以 `CLAUDE.md` 的清单为准——清单已被证明会过期且「写下来也没人真按它走」 |
| 回归 | **各插件既有测试套 0 fail** | 环境原因的失败须如实标注，不得计作产品失败，也不得计作通过 |

## Runtime Thresholds

| 项 | 阈值 | 说明 |
|---|---|---|
| 隔离实例 | 只在 scratchpad 下起，`L1_ROOT` 指向 scratchpad | **绝不触碰用户常驻 gateway（pid 29071）与 `~/.openclaw`** |
| 隔离实例的凭证残留 | **拆除后 0 份落盘副本** | 见 TH-0032；当前**未达标**，属已登记缺口 |
| 第三方 vendor | 实现类**绝不派** | 一律主会话 Sonnet 子代理（用户决策 2026-07-17） |

## Threshold Change Policy

- **验收阈值只能收紧，不能为了让某轮通过而放宽。** 若某条阈值确实不合理，
  须单开一条记录说明理由，并在 `docs/validation-log.md` 留痕；
  **「这轮达不到所以调低」永远不是合法理由**。
- **N（连续无静默失败轮数，当前 5）** 的调整属 goal 契约变更，须用户确认。
- 阈值变更不追溯已收盘的轮次。
