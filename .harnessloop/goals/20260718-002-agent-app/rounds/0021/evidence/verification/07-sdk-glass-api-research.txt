T-114 rework — ground-truth research into the real `Glass`/`glassEffect` API surface, done BEFORE
deciding how to fix Finding 2 ("the macOS 26 glass branch drops the slider intensity"). The
question that needed answering first: does SwiftUI's Glass type on macOS 26 expose any continuous
strength/opacity parameter we could just pass `intensity` into directly? Rather than guess, I read
the actual declaration shipped in the SDK installed on this machine.

=== Locating the real declaration ===
`glassEffect` is not declared in SwiftUI.swiftinterface itself — that framework re-exports from a
separate SwiftUICore.framework (visible in SwiftUI.swiftinterface's own header: `@_exported import
SwiftUICore`). The real declarations live at:
  /Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX26.5.sdk/System/Library/Frameworks/SwiftUICore.framework/Modules/SwiftUICore.swiftmodule/arm64e-apple-macos.swiftinterface

=== Conclusion ===
The ENTIRE public surface of `Glass` is: three static variants (.regular / .clear / .identity),
plus `.tint(_:)` and `.interactive(_:)` modifiers. There is no continuous strength, intensity, or
opacity parameter anywhere in this type. This directly settles the question the fix depended on:
"pass intensity straight into glassEffect" is not merely undesirable, it does not compile against
this SDK — the parameter does not exist. This is why the fix instead renders the glass as an
independent background layer (`Color.clear.glassEffect(.regular, in: ConcentricRectangle())`) and
varies THAT LAYER's `.opacity(...)`, with the actual (0,1] -> opacity mapping implemented as a pure,
unit-tested function (`AgentShellCore.ComposerGlassLayerOpacity.resolve(intensity:)` — see
03-counterproof-composer-glass-opacity.txt for its test coverage). This also settles why the
`.translucent` case's opacity must be applied to a background layer rather than to `self` directly
(the pre-fix code called `self.glassEffect(...)` directly on the composer HStack) — applying
`.opacity(...)` after that would have faded the composer's own TextField/Button along with the
glass, not just the chrome background.
