T-114 rework — destructive counter-proof for the KernelShellSettingsStorage.swift:191 default-value
claim ("0.6 restores .regularMaterial") that the reviewer flagged as possibly untrue.

Independent verification of the claim (done BEFORE writing any fix):
materialForChromeIntensity (LiquidGlassSupport.swift) buckets are:
    case ..<0.2: .ultraThickMaterial
    case ..<0.4: .thickMaterial
    case ..<0.6: .regularMaterial
    case ..<0.8: .thinMaterial
    default:     .ultraThinMaterial
All five cases are half-open, upper-bound-EXCLUSIVE ranges. The .regularMaterial bucket is
therefore [0.4, 0.6) — it does NOT include 0.6 itself, because `0.6 < 0.6` is false. A slider value
of exactly 0.6 falls through to `case ..<0.8`, i.e. .thinMaterial. The old comment's claim ("0.6
精确落在 .regularMaterial 分档的上边界，即分级函数里 case ..<0.6: return .regularMaterial 命中的
最后一个值") is mathematically wrong: it conflates "0.6 is the bucket's numeric upper bound" with
"0.6 is included in the half-open range ending at that bound" — those are not the same thing.

VERDICT: the CODE was wrong (defaultSliderValue = 0.6), not the comment's general intent (wanting
the default to look like the historical .regularMaterial). Fixed by changing the constant to 0.5
(the bucket's midpoint, not touching materialForChromeIntensity's bucket boundaries themselves,
since that function's blast radius is every chrome surface, not just "what's the default").
