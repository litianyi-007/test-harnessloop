## 结论：MVP 的关键一步补上了

**盘点查出的最致命一处不是视觉，是这一行**：

```swift
case .thinking, .toolCall, .toolResult, .capabilityChanged, .operationCompleted:
    break
```

五类 D2 事件被静默丢弃。映射层 `EventMapping.swift` **早已产出全部 11 种**，
是 UI 这层扔的。于是演示时只看得见「你一句、它一句」，**中间调了什么工具、
读了什么文件一概不可见**——对 agent 产品，这是「看不出它是 agent」。

现在：工具调用是独立行（名称 + 参数摘要 + 状态图标 + 可展开结果），
工具结果按 `toolCallID` 配对回其调用，思考默认折叠。

## 视觉：依据来自联网调研，不是印象

- 设计语言是 **Liquid Glass**（WWDC25 随 macOS 26 Tahoe 发布）；
  **当前最新的 macOS 27「Golden Gate」没有改名**，是同一套的精修。
- **用户提的「动态颗粒砂」查无官方对应物** —— 属社区实践（Flutter 等叠 noise 防色带），
  与 Reduce Transparency、性能、可读性冲突。**如实不做，不找近似物糊弄。**
- 官方分层照做：侧栏/工具栏是功能层用 Liquid Glass，**消息流是内容层永不用 `glassEffect`**，
  审批卡用 standard material、颜色只落在按钮背景。

实拍可见：**glass-prominent 的新建会话按钮**、**浮动圆角侧栏**、
**连接失败横幅从扁平色块换成 material**（状态靠红点与文字传达）。

## 评审判 REWORK，三条，其中一条是新缺陷

| # | 发现 | 性质 |
|---|---|---|
| P1 | **`toolResult` 先到时会造出两个同 `id` 的项** —— 占位项 + 无条件追加，破坏 SwiftUI `ForEach` 的唯一 identity，且结果留在占位项上 | **新缺陷**，评审发现 |
| P2 | 消息气泡仍用固定 alpha 的 `Color.*.opacity(...)`，违反「内容层必须 material」硬约束 | 违反我自己写的红线 |
| P3 | 无障碍与内容态缺实拍证据 | 证据缺口 |

**P2/P4 的实质问题不是「不好看」**：固定 alpha 的颜色**不随 Increase Contrast 提升
对比度**，系统 material 会。返工选了「严格 material」而非「层级填充色」——
后者只是缓解，前者**从构造上消除**。

**评审还指出：没有任何测试覆盖 result-before-call 这个顺序**——那正是 P1 的成因。
这是我在 brief 里没想到要求的。
