## 2. v1 的精确语法为什么被撤回

v1 提议 `<!-- verify:ignore=<span>[,<span>] -->`。T-071 逐条证伪，其中一条是决定性的：

- **`,` 做分隔符不可解析，而反例就在本协议自己身上。** 引用可以带多区间 locator：
  `foo.py:10-20,30-40`。这不是构造出来的边角情形，是 `LINE_SUFFIX_RE` 明确支持、
  语料里实际存在的写法。没有 escaping/quoting 语法就无法无歧义还原原 span——
  **而引入 escaping 语法，成本已经超过它要解决的问题**。
- `-->` 出现在 span 文本里的处置，v1 完全没规定，等于把关键行为留给实现去猜。
- **反向误命中**：按文本比较会命中同一 cleaned text 的**全部** occurrence，
  而不是作者心里的那一个。同行重复引用时静默多豁免——v1 想解决的问题原样重现。
- v1 的 `citations_ignored_collateral` 定义与自己举的例子矛盾（"单引用 + 裸 marker"
  一处算 0、按定义应算 1），不存在同时满足两者的实现。
- v1 的"零迁移"漏了 coverage schema：(b) 的口径修正会让历史 `decision.md` 里逐字
  记录的数值与重跑结果对不上。

**撤回是对的。** 为 1 条已观测的 collateral 引入一套尚未闭合的字符串协议，
代价与风险规模不成比例。

## 3. v2 的核心：一个不变量，不是一套语法

> **一个 marker 至多豁免一条引用。**

这个不变量由**目标行的引用条数**机械保证，不需要任何新语法：

### 3.1 标记识别：token 级，不是子串

**先修 §1(c)。** 一行是否携带标记，按下述规则判定，**不得用 `IGNORE_MARKER in line`**：

1. 剥掉行首的**结构前缀**：空白、`>`（blockquote，可重复）、`-`/`*`/`+` 与有序列表
   记号、以及表格行的首个 `|`。剥完得到 `body`。
2. 从 `body` 中按 HTML 注释文法取出**注释 token**（`<!--` … `-->`，非贪婪）。
3. 某个注释 token 的内容 `strip()` 后**逐字等于** `verify:ignore` → 该行携带标记。

**关键差别**：反引号 code span 内的 `` `<!-- verify:ignore -->` `` 是**文本**，不是注释
token——先取 code span、再取注释 token，两者不重叠。因此"讨论这个标记"不再等于
"启用这个标记"。§1(c) 的复现输入在新规则下：该行不携带标记，两条引用照常被检查。

### 3.1b 作用域

| 标记位置 | 目标行 |
|---|---|
| **独占**（`body` 去掉注释 token 后无剩余非空白内容） | **下一行** |
| **行内**（`body` 去掉注释 token 后仍有内容） | **该行自身** |

两种形式都保留。T-071 反提案只保留独占形式，**那会打断 markdown 表格**——表格中间
插入一个独立注释行会终止表格，而表格行恰是引用密集处。实测语料：多引用行共 144 行，
表格行 12 行（8%）——比例不高，但足以让"只允许独占"变成一条逼人破坏文档结构的规则。

**"独占"的字形判定按 §3.1 第 1 步剥完前缀之后做**，所以 `> <!-- verify:ignore -->`
（blockquote 内）与 `| <!-- verify:ignore -->` 都算独占形式，不因缩进或引用层级而改判。

### 3.1c 重叠：同一目标行被多个标记命中

一个目标行可能同时被"上一行的独占标记"与"自身的行内标记"命中，或被同一行的两个
注释 token 命中。规则：

- **归并为一次豁免**，不叠加：不变量仍是"至多豁免一条引用"。
- 同时报 `ignore-marker-redundant`（每个目标行至多一条），detail 列出全部命中的标记
  行号。理由：重叠必然意味着有一个标记是多余的，而多余的标记正是 §3.2 要消灭的
  陈旧物；静默归并会把它藏起来。

### 3.2 目标行必须恰好有 1 条引用候选

| 目标行引用数 | 结果 |
|---|---|
| 1 | 豁免该条。**这是唯一的正常情形** |
| 0 | 违规 `ignore-marker-stale` |
| ≥ 2 | 违规 `ignore-scope-ambiguous` |

**`0` 也判违规**，因为陈旧 marker 是当前形式的一个静默失效模式：引用被修好或删掉后，
marker 留在原地，继续豁免**此后落到那一行的任何东西**。实测既有语料里就有这种
marker——它一条引用都没豁免，却被字段计成豁免了 5 条。

**≥2 的处置不是新语法，是拆行**：把那一句拆成两行（markdown 段落内的换行是软换行，
渲染不变），或者对确实不该被反引号括起来的散文路径去掉反引号。多引用行里 92% 不在
表格中，拆行直接可用；余下表格行需要重排单元格，属已知摩擦，见 §7。

### 3.3 occurrence 歧义由此消失

T-071 指出 v1 的文本比较无法表达"同一行同一文本出现两次、只豁免第一次"。
v2 里这个问题**不存在**：目标行只允许有 1 条引用候选，多于 1 条直接违规。
不变量把整类歧义关在门外，而不是去解析它。

## 4. 历史豁免：按文件摘要，冻结名单

严格规则会让**现有语料变红**——Rule B 实际扫描范围（`rounds/*/reviews/`）内含标记的
文件共 **3 份**（三份 `adversarial-review.md`），其中的标记只有 1 个满足 §3.2。
（v2 此处写"4 份"是**错的**：把 `.hopper/handoffs/T-065-output.md` 算了进去，
而 `.hopper/handoffs/` 不在 Rule B 扫描范围内。T-072 指出，已更正。）

历史评审产物**不得为了让机械门通过而修改**（v0.12.0 E1），所以必须有豁免机制。

`.harnessloop/setup/ignore-legacy.json`（版本化、可 diff）：

```json
{"version": 1, "frozen": true, "legacy": [{"path": "<项目内相对路径>", "sha256": "<摘要>"}]}
```

### 4.1 摘要与路径口径（写死，不留给实现猜）

- **摘要 = 文件原始字节的 SHA-256**。不做任何规范化：不转行尾、不去 BOM、
  不 strip 尾随空白。理由：任何规范化都是一个需要跨平台一致的额外契约，而这里
  只需要"这份文件与登记时逐字节相同"这一个判断。
- **路径 = 相对项目根的 POSIX 形式**（`/` 分隔，无 `./` 前缀，不含 `..`）。
- **比较前做 canonical 解析并做 containment 检查**（复用 `_canonical` / `_is_contained`）：
  名单条目若解析到项目外、或该路径是 symlink，**一律不豁免**并报
  `ignore-legacy-path-rejected`。这条不是洁癖——本项目在 v0.20.0/v0.22.0/v0.25.0
  连续三次被"路径字面量 ≠ 文件系统身份"咬过（父目录逃逸、symlink 逃逸、
  大小写不敏感卷），名单是又一个"看起来像路径的字符串"，同一判据必须适用。
- **同一性用 `_same_dir` 同族的文件级判据**：先 canonical，再比较，避免大小写不敏感
  卷上 `Reviews/x.md` 与 `reviews/x.md` 被当成两份文件。

### 4.2 名单冻结（T-072 阻断项）

`"frozen": true` 一旦置位，**名单只能删不能增**。新增条目须显式改为 `false`、
在同一提交里写明理由，并且该提交必然出现在 diff 里。

不冻结的话，legacy 名单本身就是一条绕过通道：写一份新评审、把它加进名单、
它就合法地拿到了旧语义——本规格想关的门被自己开的后门抵消。

**实现须断言**：`frozen: true` 时名单条目数不得多于上一次提交的条目数——这个断言
无法在单次运行内自证（需要历史），故落为 **CI 层检查**而非机械门内检查，并在规格
里明写这是一个**协议外的补充守卫**，不声称机械门自己防住了追加。

### 4.3 为什么按文件摘要而不是按 round 或协议版本号

T-071 建议按 round/协议版本分流。按 round 豁免会留一个洞：一个被标为 legacy 的 round
日后新增一份评审，它也自动获得旧语义。按文件摘要是内容寻址的，**只**豁免今天确实
存在的那 3 份，任何新文件在任何地方都拿严格规则；且文件一旦被编辑即失去豁免——
正是 E1 要的激励方向。

**不用 mtime**：时间戳不进 git、跨机器不可复现、可被 touch 篡改。

## 5. 计数口径修正

### 5.1 `citations_ignored_explicit` 只计真引用

先跑完整的 citation 判定，再对判定为引用者计数。**纯口径修正，被豁免的集合一条不变。**

### 5.2 新增 `citations_ignored_unscoped`

**定义（唯一，无例外）**：被豁免的引用中，由**旧语义（行粒度）标记**豁免的条数。
严格语义下的豁免**恒定贡献 0**——不是"至多 1"，是 0，因为它们受不变量约束、
按定义不属于 unscoped。

由此该字段严格等于"来自 legacy 名单文件的豁免量"，是 B2b 预登记要设阈的那个量
（建议阈值 `== 0`：新评审不产生任何未受约束的豁免）。

v2 的 J10 把该字段描述成"严格规则下任何 marker → 至多 1"，与本定义矛盾（T-072 抓到）。
以本节为准，J10 已按此改写。

v1 的 `citations_ignored_collateral` 维持撤回。

### 5.3 coverage schema 版本（T-071 第 5 项，v1 漏掉的）

口径修正会让历史 `decision.md` 里逐字记录的 coverage 数值与重跑结果对不上。
`--json` 输出与 coverage 行新增 `coverage_schema: <int>`，本次修正把它推到 `2`。

历史记录不改、不追认，**但从此可判读**：schema 1 的数字按 span 口径读，
schema 2 按引用口径读。不加这个字段，两个不同口径的数会被后来人当成同一件事对比。

## 6. 验收（teeth）

每条须有破坏性反证：拆掉实现，对应检查立即变红。

| # | 断言 | 破坏性反证 |
|---|---|---|
| J1 | 独占标记 + 下一行恰 1 条引用 → 豁免该条；同文件其它行照常被检查 | 扩大作用域到多行 → 红 |
| J2 | 行内标记 + 该行恰 1 条引用 → 豁免该条（表格行可用） | 取消行内形式 → 红 |
| J3 | 目标行 2 条引用 → `ignore-scope-ambiguous`，**两条都不豁免** | 退回行粒度 → 两条都被豁免 → 红 |
| J4 | 目标行 0 条引用 → `ignore-marker-stale` | 去掉 stale 检查 → 陈旧标记静默存活 → 红 |

## 7. 已知摩擦（如实登记，不掩饰）

- **表格行有 ≥2 条引用且需要豁免时，无法靠拆行解决**，只能重排单元格或去掉某个反引号。
  语料里这种行至多 12 行，其中真正需要豁免的是极少数。属可接受但真实的成本。
- **`ignore-marker-stale` 会让"写了但没用上"的注释变成硬错误。** 有意为之（§3.2），
  但作者第一次遇到会觉得突兀。错误 detail 必须写清目标行、该行找到 0 条引用、
  以及两种合法作用域形式。
- **legacy 名单需人工写一次**（当前 3 份文件的摘要）。之后除非有人违反 E1 去改历史
  评审，不需再动。
- **名单冻结的断言落在 CI 而非机械门**（§4.2）：机械门单次运行看不到历史，无法自证
  "名单没被追加过"。**规格明写这一点，不声称机械门防住了追加。**
- **`coverage_schema` 只解决"从此可判读"，不解决"历史数字本身"**：schema 1 的记录
  仍是 span 口径，不追认、不重算。
- **本规格不处理 `.hopper/handoffs/` 下的评审产物**——它们不在 Rule B 扫描范围内，
  今天的标记在那里没有任何作用。B2b 把评审入树后这一点会改变，届时须复核。

## Acceptance verification (6/6)

### 1. §6 的五个靶子 — FAIL

1. **§6.1 字面比较 — FAIL。** `,` 同时是列表分隔符和合法引用文本的一部分；当前实现还明确支持逗号多区间 locator。反例：引用 `` `src/a.py:44-46,443-507` `` 是一个 citation，但 `verify:ignore=src/a.py:44-46,443-507` 按 §3.2 只能拆成两个错误名字。`-->` 也没有转义规则；反例 `@@wiki/a-->b.py` 会被当前 alias-first 分支认作 citation，却会在 marker 内提前终止 HTML comment。证据：`verify_protocol.py:341-350,598-614,698-714`，规格 `:70-81`。
2. **§6.2 unmatched — FAIL。** “目标只出现在本行或下一行之一”若把作用域定义为二者的并集，本身不误伤；缝在于同一清洗后文本出现两次。反例：marker 点名 `missing/x.py`，其本行是本意豁免，下一行又出现同名真实引用；两处都会被豁免、目标已命中，因而没有 `ignore-span-unmatched`。规格没有定义零次、一次、多次 occurrence 的不同语义。
3. **§6.3 collateral — FAIL。** 定义与示例直接矛盾：`:93` 规定“被豁免且未被精确点名”都计入，因此单引用 + 裸 marker 应为 1；`:95` 却规定为 0。裸 marker 不携带“本意豁免哪条”的信息，故无法推导真实 collateral。
4. **§6.4 保留裸形式 — FAIL。** 当前方案只是“可见”，不是“收窄”：规格明确不报违规（`:102-119`），B2b 的 `==0` 也只是建议且不属于本规格的 teeth（`:99-100,142`）。E1 并未造成“全局继续合法或修改历史评审”二选一；可对旧 round 维持旧语义、对启用新协议的 round 施加新规则。并且被引用的 E1 原文禁止的是修改 finding 的实质内容、结论或证据对象来躲门，不是证明“任何 marker 迁移都禁止”：`docs/rule-ab-pilot-budget-20260728.md:61-66`。
5. **§6.5 计数修正 — FAIL。** I5 只锁住 violation `kind/detail`，没有锁住 coverage。规格自己要求 coverage 逐字同步进 `decision.md`（`:140-141`），打印又直接包含该字段（`verify_protocol.py:2841-2849`）；重定义数值和新增字段都会使历史快照与新版重跑不同。这里需要显式的 telemetry schema 迁移，而不能称“零迁移”。

### 2. 精确形式 `verify:ignore=<span>` 的绕过面 — FAIL

可复现实测（直接加载当前 `pathish_citations`）：

```text
'src/a,b.py'                 -> ['src/a,b.py']
'src/a.py:44-46,443-507'     -> ['src/a.py:44-46,443-507']
'@@wiki/a-->b.py'            -> ['@@wiki/a-->b.py']
comma split                  -> ['src/a.py:44-46', '443-507']
HTML comment data            -> ' verify:ignore=@@wiki/a'
HTML residual data           -> 'b.py -->'
```

复现入口：

```bash
python - <<'PY'
import runpy
from html.parser import HTMLParser
m = runpy.run_path("harnessloop/plugins/harnessloop/skills/harnessloop-loop/scripts/verify_protocol.py")
f = m["pathish_citations"]
for x in ("src/a,b.py", "src/a.py:44-46,443-507", "@@wiki/a-->b.py"):
    print(repr(x), "->", f(f"cite `{x}`")[0])
print("comma split ->", "src/a.py:44-46,443-507".split(","))
class H(HTMLParser):
    def handle_comment(self, x): print("HTML comment data ->", repr(x))
    def handle_data(self, x):
        if x.strip(): print("HTML residual data ->", repr(x))
H().feed("<!-- verify:ignore=@@wiki/a-->b.py -->")
PY
```

逐项判断：

- **逗号 — FAIL：** 除合法文件名 `src/a,b.py` 外，当前协议自己的多区间 locator 就是必现反例。没有 escaping/quoting grammar 时无法无歧义恢复原 span。
- **`-->` — FAIL：** 规格没有规定拒绝、编码或解析方式。即使实现选择从原始行取最后一个 `-->`，它也已偏离该构造的 HTML comment 语义；不能把关键行为留给实现猜测。
- **大小写、尾斜杠、`./` — NOTE（fail-closed，但须写清）：** 仅 `strip()` 和 `\`→`/` 意味着 `src/app.py`≠`SRC/App.py`、`rounds/0001`≠`rounds/0001/`、`src/app.py`≠`./src/app.py`。它们不会静默扩大豁免，因为应触发 unmatched，但会造成作者认为是同一路径却点名失败；错误 detail 必须打印 marker 原文、清洗后目标和候选。
- **反斜杠与外侧空白 — NOTE：** 若 marker entry 也逐项执行相同清洗，则 `src\app.py` 会匹配 `src/app.py`，外侧空白也会消失；规格只说比较对象是清洗后的 span，没有明确“先 split 再逐 entry 清洗”。反例 `verify:ignore=src/a.py, src/b.py` 的第二项是否保留前导空格，当前文字不能唯一决定。
- **反向误命中 — FAIL：** 同一 cleaned text 的所有 occurrence 都会命中，而不是只命中作者心中的那个 occurrence；这在同一行重复引用或 marker 的两个行位中重复引用时，会静默多豁免。

### 3. `ignore-span-unmatched` 是否误伤 — FAIL

- **只出现在两个行位之一：PASS。** 若规范明确“marker scope 是两个行位的并集”，存在于任一行就算命中是自洽的，不应按另一个空行再报错。
- **重复 occurrence：FAIL。** 具体反例：

  ```markdown
  本意是散文例子 `missing/x.py`。 <!-- verify:ignore=missing/x.py -->
  下一行却把同名文件当证据再次引用：`missing/x.py`
  ```

  按 `:77,85`，两处文本完全相等，均被豁免，unmatched 为 0；按 `:93` 两处又都属“精确点名”，collateral 仍为 0。该组合同时绕过 stale 检测和 collateral 监测。
- **违规基数未定义：FAIL。** 一个 marker 点名 3 个不同 span、只有 2 个存在，应产生 **1 条** `ignore-span-unmatched`（对唯一缺失目标逐目标报，detail 含 review、marker 行号和缺失的 cleaned target），不是对 3 个名字都报错。重复列出同一名字应另判 syntax error 或去重；规格必须二选一并加精确计数 fixture。

当前两行作用域的可复现依据是 `verify_protocol.py:689-691`；现有 fixture 也明确同时覆盖“上一行 marker”和“同行 marker”（`harnessloop/scripts/validate.py:1258-1280`）。

### 4. `citations_ignored_collateral` 的定义 — FAIL

该字段无法从现有语法度量“作者本意以外的豁免”，最多能度量“未作用域化的豁免”：

- **把本就该豁免的算成 collateral：** 裸 marker 下一行有 3 个均为散文例子的引用，实际 collateral=0；`:93/:96` 会报 3。
- **漏掉真实 collateral（裸形式）：** 裸 marker 已陈旧，下一行后来只有 1 个真实 dangling citation；`:95` 强制报 0，但实际 collateral=1。
- **漏掉真实 collateral（精确形式）：** 上一节的同名双 occurrence 反例中只想豁免第一个，第二个仍被文本级点名连带豁免；字段报 0，实际 collateral=1。
- **定义内部矛盾：** `:93` 对“单引用 + 裸 marker”算 1，`:95` 算 0；不存在同时满足两者的实现。

建议把字段改名并诚实定义为 `citations_ignored_unscoped`：逐 occurrence 统计所有由裸 marker 跳过、且按完整 classifier 本会进入 `cited` 的 citation。不要称其为实际 collateral；实际意图没有输入，机器无法恢复。

### 5. “零迁移” — FAIL（高严重度，实施前必须处理）

I5 只证明 violation 判定兼容，不证明输出契约兼容。当前纪律要求 coverage 行逐字入 `decision.md`，所以 §3.1 重定义旧字段会使同一历史 round 的新版重跑与当时记录不一致；§3.4 新增字段又会改变整行字节。它不要求改历史文件，但它是一次真实的 **coverage schema migration**。

此外，按规格 §3.1 的口径对当前 checkout 三份 setup-wizard 评审重算，结果是 **14→8，不是规格 `:31` 的 14→6**：

```text
rounds/0001/reviews/adversarial-review.md: old=2, citation_count=2
rounds/0002/reviews/adversarial-review.md: old=5, citation_count=2
rounds/0003/reviews/adversarial-review.md: old=7, citation_count=4
TOTAL: old=14, citation_count=8
```

复现命令：

```bash
python - <<'PY'
import runpy
from pathlib import Path
m = runpy.run_path("harnessloop/plugins/harnessloop/skills/harnessloop-loop/scripts/verify_protocol.py")
f, marker = m["pathish_citations"], m["IGNORE_MARKER"]
root = Path(".harnessloop/goals/20260716-001-setup-wizard")
old_total = new_total = 0
for p in sorted(root.glob("rounds/*/reviews/*.md")):
    lines = p.read_text().splitlines()
    raw = "\n".join(lines)
    old = f(raw)[2]
    new = sum(
        len(f(line.replace(marker, ""))[0])
        for i, line in enumerate(lines)
        if marker in line or (i > 0 and marker in lines[i - 1])
    )
    old_total += old; new_total += new
    print(f"{p.relative_to(root)}: old={old}, citation_count={new}")
print(f"TOTAL: old={old_total}, citation_count={new_total}")
PY
```

该命令对每个满足 `marker in line or marker in previous_line` 的行，移除同行 marker 后把该行重新送入当前 `pathish_citations`，累计返回的 `cited` occurrence。这个口径正是 `:64-68` 所写的“本来会进入 cited”；差异说明实施前必须重跑并公布 corpus 基线。

处置应为：

1. 冻结 `citations_ignored_explicit` 的旧语义，新增名字准确的新字段；不要静默重定义已有字段。
2. coverage 输出增加 `coverage_schema=v2` 及 verifier 版本/commit；明确历史 `decision.md` 是与当时版本绑定的快照，新版 replay 不做跨 schema 字节比较。
3. 若“历史重跑字节相同”真是硬要求，则必须用旧 verifier/schema replay 旧 round，或按 round 协议版本输出旧 schema。
4. I5 扩为两组 fixture：violation parity，以及明确列出 v1→v2 预期字段差异的 telemetry migration 测试。

## 第 6 项：值不值得做 — FAIL（否决当前 §3.2/§3.3）

**取舍：本轮不值得引入当前精确语法。** pilot 的实测是 1 条 collateral、绝对量小；规格自己的语料是 679 个引用行中 79% 单引用、存量 marker 仅 4 份。与此同时，新语法已经引入任意合法路径分隔、HTML 终止、两行 occurrence、重复目标和诊断基数五类新状态，而它仍不能表达“同文本两个 occurrence 只豁免一个”。

“只修 (b) + 加一个字段”如果仍然只记录不阻断，**不够**；但无需为此引入 payload 语法。建议本轮采用更小的防御性规则：

1. 按第 5 项做 versioned telemetry；新增 `citations_ignored_unscoped`，统计真实被裸 marker 跳过的 citation occurrence。
2. 对启用新协议的 round，沿用现有裸 marker，但要求它是独立行、只作用于紧邻下一行，且下一行必须恰有 1 个 citation candidate；0 个报 stale，>1 个报 `ignore-scope-ambiguous`。作者可把罕见的多引用句拆行，不需要新 escaping grammar。
3. 历史 round 保持旧语义；用明确的 round/protocol version 或不可变 legacy baseline 分流，禁止依赖 mtime。这样不改 4 份历史评审，也能拦住新 round 的大面积连带豁免。
4. 只有后续实测证明“拆行”形成显著负担，才另立精确语法；届时必须先定义可逆编码和 occurrence 作用域。

这比当前方案更贴合风险规模：它机械阻止一个 marker 跳过多条 citation，却不为 1 个已观测 collateral 引入一套尚未闭合的字符串协议。

§5.2 定义：`citations_ignored_unscoped` = 由**旧语义（行粒度）**豁免的引用条数，并写「严格规则下…等价于来自 legacy 文件的豁免量」。  
⇒ 严格模式 marker（即使豁免 1 条）**不应**计入 unscoped，应计 **0**。

J10 却写：「严格规则下任何 marker → **至多 1**」。  
那是把 unscoped 写成了「忽略条数上限」而不是「旧语义豁免量」。  
破坏性反证「字段恒 0」也无法区分「实现漏计 legacy」与「严格全 0 的正确行为」。

**应改为：** legacy 文件中一行粒度 marker 豁免 3 条 → 报 3；**任意严格模式文件 → 恒 0**（B2b 阈值 `==0` 才有意义）。

    57	## 3. v2 的核心：一个不变量，不是一套语法
    58	
    59	> **一个 marker 至多豁免一条引用。**
    60	
    61	这个不变量由**目标行的引用条数**机械保证，不需要任何新语法：
    62	
    63	### 3.1 标记识别：token 级，不是子串
    64	
    65	**先修 §1(c)。** 一行是否携带标记，按下述规则判定，**不得用 `IGNORE_MARKER in line`**：
    66	
    67	1. 剥掉行首的**结构前缀**：空白、`>`（blockquote，可重复）、`-`/`*`/`+` 与有序列表
    68	   记号、以及表格行的首个 `|`。剥完得到 `body`。
    69	2. 从 `body` 中按 HTML 注释文法取出**注释 token**（`<!--` … `-->`，非贪婪）。
    70	3. 某个注释 token 的内容 `strip()` 后**逐字等于** `verify:ignore` → 该行携带标记。
    71	
    72	**关键差别**：反引号 code span 内的 `` `<!-- verify:ignore -->` `` 是**文本**，不是注释
    73	token——先取 code span、再取注释 token，两者不重叠。因此"讨论这个标记"不再等于
    74	"启用这个标记"。§1(c) 的复现输入在新规则下：该行不携带标记，两条引用照常被检查。
    75	
    76	### 3.1b 作用域
    77	
    78	| 标记位置 | 目标行 |
    79	|---|---|
    80	| **独占**（`body` 去掉注释 token 后无剩余非空白内容） | **下一行** |
    81	| **行内**（`body` 去掉注释 token 后仍有内容） | **该行自身** |
    82	
    83	两种形式都保留。T-071 反提案只保留独占形式，**那会打断 markdown 表格**——表格中间
    84	插入一个独立注释行会终止表格，而表格行恰是引用密集处。实测语料：多引用行共 144 行，
    85	表格行 12 行（8%）——比例不高，但足以让"只允许独占"变成一条逼人破坏文档结构的规则。
    86	
    87	**"独占"的字形判定按 §3.1 第 1 步剥完前缀之后做**，所以 `> <!-- verify:ignore -->`
    88	（blockquote 内）与 `| <!-- verify:ignore -->` 都算独占形式，不因缩进或引用层级而改判。
    89	
    90	### 3.1c 重叠：同一目标行被多个标记命中
    91	
    92	一个目标行可能同时被"上一行的独占标记"与"自身的行内标记"命中，或被同一行的两个
    93	注释 token 命中。规则：
    94	
    95	- **归并为一次豁免**，不叠加：不变量仍是"至多豁免一条引用"。
    96	- 同时报 `ignore-marker-redundant`（每个目标行至多一条），detail 列出全部命中的标记
    97	  行号。理由：重叠必然意味着有一个标记是多余的，而多余的标记正是 §3.2 要消灭的
    98	  陈旧物；静默归并会把它藏起来。
    99	
   100	### 3.2 目标行必须恰好有 1 条引用候选
   101	
   102	| 目标行引用数 | 结果 |
   103	|---|---|
   104	| 1 | 豁免该条。**这是唯一的正常情形** |
   105	| 0 | 违规 `ignore-marker-stale` |
   106	| ≥ 2 | 违规 `ignore-scope-ambiguous` |
   107	
   108	**`0` 也判违规**，因为陈旧 marker 是当前形式的一个静默失效模式：引用被修好或删掉后，
   109	marker 留在原地，继续豁免**此后落到那一行的任何东西**。实测既有语料里就有这种
   110	marker——它一条引用都没豁免，却被字段计成豁免了 5 条。
   111	
   112	**≥2 的处置不是新语法，是拆行**：把那一句拆成两行（markdown 段落内的换行是软换行，
   113	渲染不变），或者对确实不该被反引号括起来的散文路径去掉反引号。多引用行里 92% 不在
   114	表格中，拆行直接可用；余下表格行需要重排单元格，属已知摩擦，见 §7。
   115	
   116	### 3.3 occurrence 歧义由此消失
   117	
   118	T-071 指出 v1 的文本比较无法表达"同一行同一文本出现两次、只豁免第一次"。
   119	v2 里这个问题**不存在**：目标行只允许有 1 条引用候选，多于 1 条直接违规。
   120	不变量把整类歧义关在门外，而不是去解析它。

   134	{"version": 1, "frozen": true, "legacy": [{"path": "<项目内相对路径>", "sha256": "<摘要>"}]}

   137	### 4.1 摘要与路径口径（写死，不留给实现猜）
   138	
   139	- **摘要 = 文件原始字节的 SHA-256**。不做任何规范化：不转行尾、不去 BOM、
   140	  不 strip 尾随空白。理由：任何规范化都是一个需要跨平台一致的额外契约，而这里
   141	  只需要"这份文件与登记时逐字节相同"这一个判断。
   142	- **路径 = 相对项目根的 POSIX 形式**（`/` 分隔，无 `./` 前缀，不含 `..`）。
   143	- **比较前做 canonical 解析并做 containment 检查**（复用 `_canonical` / `_is_contained`）：
   144	  名单条目若解析到项目外、或该路径是 symlink，**一律不豁免**并报
   145	  `ignore-legacy-path-rejected`。这条不是洁癖——本项目在 v0.20.0/v0.22.0/v0.25.0
   146	  连续三次被"路径字面量 ≠ 文件系统身份"咬过（父目录逃逸、symlink 逃逸、
   147	  大小写不敏感卷），名单是又一个"看起来像路径的字符串"，同一判据必须适用。
   148	- **同一性用 `_same_dir` 同族的文件级判据**：先 canonical，再比较，避免大小写不敏感
   149	  卷上 `Reviews/x.md` 与 `reviews/x.md` 被当成两份文件。
   150	
   151	### 4.2 名单冻结（T-072 阻断项）
   152	
   153	`"frozen": true` 一旦置位，**名单只能删不能增**。新增条目须显式改为 `false`、
   154	在同一提交里写明理由，并且该提交必然出现在 diff 里。
   155	
   156	不冻结的话，legacy 名单本身就是一条绕过通道：写一份新评审、把它加进名单、
   157	它就合法地拿到了旧语义——本规格想关的门被自己开的后门抵消。
   158	
   159	**实现须断言**：`frozen: true` 时名单条目数不得多于上一次提交的条目数——这个断言
   160	无法在单次运行内自证（需要历史），故落为 **CI 层检查**而非机械门内检查，并在规格
   161	里明写这是一个**协议外的补充守卫**，不声称机械门自己防住了追加。
   162	
   163	### 4.3 为什么按文件摘要而不是按 round 或协议版本号
   164	
   165	T-071 建议按 round/协议版本分流。按 round 豁免会留一个洞：一个被标为 legacy 的 round
   166	日后新增一份评审，它也自动获得旧语义。按文件摘要是内容寻址的，**只**豁免今天确实
   167	存在的那 3 份，任何新文件在任何地方都拿严格规则；且文件一旦被编辑即失去豁免——
   168	正是 E1 要的激励方向。
   169	
   170	**不用 mtime**：时间戳不进 git、跨机器不可复现、可被 touch 篡改。

   628	def pathish_citations(markdown_text: str) -> tuple[list[str], int, int, int, bool]:
   629	    """Extract citation spans that look like file paths.
   630	
   631	    Beyond the protocol prefixes, any slash-containing span with a file
   632	    extension, a trailing slash, or a `..` segment is treated as a path so
   633	    that citations of source/test files (e.g. `src/app.py`) are verified too.
   634	    Spans with spaces, URLs, flags, and variables are ignored, as are
   635	    regex/glob patterns (`_looks_like_pattern`), bare-domain URLs
   636	    (`_looks_like_bare_domain`), templated paths containing an
   637	    angle-bracket placeholder (`_looks_like_placeholder`, e.g.
   638	    `goals/<id>/data-contract.md`), and home-relative, POSIX-absolute, or
   639	    Windows-absolute paths naming a location outside the project
   640	    (`_looks_like_out_of_project`, e.g. `~/.llm-wiki/x.md`, `/etc/hosts`, or
   641	    `C:/Users/x`). A line carrying (or immediately following a line that
   642	    carries) the `<!-- verify:ignore -->` marker has all of its citations
   643	    skipped — see module docstring.

   646	    judgment criterion 2, "ignore-marker misuse must not go unmonitored"):
   647	    before this, the ignore branch below `continue`d without counting
   648	    anything, so a review could sprinkle `<!-- verify:ignore -->` over
   649	    genuinely dangling citations and empty Rule B out while `coverage` /
   650	    exit code / `--json` all kept reporting clean — the exact same shape of
   651	    silent exemption `citations_exempt_external` closed for the `~/...`
   652	    absolute-path gap, just for a different escape hatch. `ignored_explicit`
   653	    counts every backtick span found on a line the marker exempts (deliberately
   654	    every span on that line, not only ones that would otherwise have looked
   655	    pathish — the marker is documented to exempt "every citation on it", and
   656	    a conservative over-count here is the correct bias for a misuse monitor).

   658	    `markdown_text`), which the caller accumulates into the file-level
   659	    `review_files_with_ignore` coverage field rather than per-span.
   660

   662	    contains `/` (so it is clearly meant as a path) but whose tail has no
   663	    file extension, no trailing `/`, and no `..` segment — e.g. `src/pkgdir`
   664	    — falls through the shape branch below without ever being appended to
   665	    `cited`, and before this field existed that drop was silent. This is
   666	    also the cheapest way to turn a real dangling citation green: delete the
   667	    file extension from an already-red span and it vanishes from every
   668	    coverage field, not just this one. (PR-3: an `@@<alias>/...` span no
   669	    longer takes this exit even with an extension-less tail — e.g.
   670	    `@@wiki/kernel` — because the alias-shape branch above matches first
   671	    and appends it to `cited` unconditionally; only a non-`@@` span can
   672	    still land in `shape_dropped`.)

   675	    has_ignore_marker)`: `cited` is the list of spans to existence-check,
   676	    `exempt_external` is a count of spans skipped specifically by
   677	    `_looks_like_out_of_project` (not any other exemption) — the caller
   678	    accumulates this into the `citations_exempt_external` coverage field —

   680	    `citations_shape_dropped`, and `review_files_with_ignore` respectively

   688	    for i, line in enumerate(lines):

   690	            ignored_explicit += len(CODE_SPAN.findall(line))
   691	            continue
   692	        for span in CODE_SPAN.findall(line):
   693	            cleaned = span.strip().replace("\\", "/")

   695	                continue
   696	            if cleaned.startswith(("-", "$", "<")):
   697	                continue
   698	            if ALIAS_CITATION_RE.match(cleaned):

   701	                # span belongs to is decided by its syntax alone, before any

  1013	def _resolve_in_root(root: Path, rel: str) -> Path | None:
  1014	    """PR-3 §2.5's two orthogonal containment defenses, applied to an
  1015	    external reference root: `root` must already be canonical (this is the
  1016	    same "pinned domain" `_is_contained_pinned` requires — see its
  1017	    docstring).
  1018	
  1019	    Defense 1 — literal traversal rejection, applied to the raw text before
  1020	    any join: an empty `rel`, or one starting with `/` or `~`, a Windows
  1021	    drive-absolute form, or containing a `..` segment, is rejected before

  1048	def _resolve_case_exact(root: Path, rel: str) -> Path | None:
  1049	    """Walk `rel`'s segments under `root` one directory entry at a time via
  1050	    `os.scandir`, matching each segment name *exactly* (byte-for-byte
  1051	    string comparison), never through `Path.exists()`/`Path.is_dir()` --
  1052	    G10: those two delegate to the host filesystem's own comparison, which
  1053	    is case-*insensitive* (but case-preserving) on a default macOS or
  1054	    Windows filesystem, so a citation with the wrong case for a real file
  1055	    would otherwise resolve there (measured directly against this project's
  1056	    own external root: `@@wiki/KERNEL/FACTS.MD` resolves via `.exists()` on
  1057	    macOS even though the real file is `kernel/facts.md`).
  1058

  1062	    that folding.

+### 1. §9.1：token 级 marker 识别是否闭合 — FAIL
+
+方向正确，但 §3.1 的“先取 code span、再取 HTML 注释 token”还不是一个唯一算法。
+
+| 构造 | v3 能否唯一决定 | 证据 / 结果 |
+|---|---|---|
+| `` `x --> y` <!-- verify:ignore --> `src/x.py` `` | 可以 | `-->` 位于 code span 区间内时不得关闭外部注释；真实 marker 在 span 外，应该识别。这一普通情形可闭合。 |
+| `<!-- note \` --> <!-- verify:ignore --> \`tail\` and \`no/such.py\`` | **不能** | 当前 `CODE_SPAN = re.compile(r"`([^`]+)`")` 先扫时，第一个 match 是 `' --> <!-- verify:ignore --> '`，会把真实 marker 错遮成 code span；按 Markdown 的 HTML-comment 优先级解析则该 marker 在注释外，应被识别。实测：`marker inside first code-span match=True`。 |
+| 多行 `<!--\nverify:ignore\n-->\n\`no/such.py\`` | **不能** | “HTML 注释文法”允许跨行 token，其内容 `strip()` 后等于 marker；“一行是否携带标记”又暗示逐物理行扫描。两种实现分别会识别/不识别，且识别时 marker 行和目标行也未定义。 |
+| `<!-- broken <!-- verify:ignore --> \`no/such.py\`` | **不能** | 非贪婪 regex 得到唯一内容 `' broken <!-- verify:ignore '`，不识别；搜索内层精确注释的容错实现会识别。未规定 malformed comment 是普通文本、marker，还是违规。 |
+| `<!-- verify:ignore --><!-- rationale -->` | **不能** | 若 §3.1b“去掉注释 token”指去掉全部 comment tokens，则该行独占、目标是下一行；若只去掉命中的 marker token，则 `<!-- rationale -->` 是剩余内容、该行变成行内并对自身报 stale。 |
+| `<!-- note --> <!-- verify:ignore --> \`no/such.py\`` | 可以 | 多 token 中只要一个 token 的内容精确等于 `verify:ignore`，§3.1 第 3 步足以认定该行携带 marker。 |

+```text

+### 1. §9.1：token 级 marker 识别是否闭合 — FAIL
+
+方向正确，但 §3.1 的“先取 code span、再取 HTML 注释 token”还不是一个唯一算法。
+
+| 构造 | v3 能否唯一决定 | 证据 / 结果 |
+|---|---|---|
+| `` `x --> y` <!-- verify:ignore --> `src/x.py` `` | 可以 | `-->` 位于 code span 区间内时不得关闭外部注释；真实 marker 在 span 外，应该识别。这一普通情形可闭合。 |
+| `<!-- note \` --> <!-- verify:ignore --> \`tail\` and \`no/such.py\`` | **不能** | 当前 `CODE_SPAN = re.compile(r"`([^`]+)`")` 先扫时，第一个 match 是 `' --> <!-- verify:ignore --> '`，会把真实 marker 错遮成 code span；按 Markdown 的 HTML-comment 优先级解析则该 marker 在注释外，应被识别。实测：`marker inside first code-span match=True`。 |
+| 多行 `<!--\nverify:ignore\n-->\n\`no/such.py\`` | **不能** | “HTML 注释文法”允许跨行 token，其内容 `strip()` 后等于 marker；“一行是否携带标记”又暗示逐物理行扫描。两种实现分别会识别/不识别，且识别时 marker 行和目标行也未定义。 |
+| `<!-- broken <!-- verify:ignore --> \`no/such.py\`` | **不能** | 非贪婪 regex 得到唯一内容 `' broken <!-- verify:ignore '`，不识别；搜索内层精确注释的容错实现会识别。未规定 malformed comment 是普通文本、marker，还是违规。 |
+| `<!-- verify:ignore --><!-- rationale -->` | **不能** | 若 §3.1b“去掉注释 token”指去掉全部 comment tokens，则该行独占、目标是下一行；若只去掉命中的 marker token，则 `<!-- rationale -->` 是剩余内容、该行变成行内并对自身报 stale。 |
+| `<!-- note --> <!-- verify:ignore --> \`no/such.py\`` | 可以 | 多 token 中只要一个 token 的内容精确等于 `verify:ignore`，§3.1 第 3 步足以认定该行携带 marker。 |

+|---|---|---|

+### 1. §9.1：token 级 marker 识别是否闭合 — FAIL
+
+方向正确，但 §3.1 的“先取 code span、再取 HTML 注释 token”还不是一个唯一算法。
+
+| 构造 | v3 能否唯一决定 | 证据 / 结果 |
+|---|---|---|
+| `` `x --> y` <!-- verify:ignore --> `src/x.py` `` | 可以 | `-->` 位于 code span 区间内时不得关闭外部注释；真实 marker 在 span 外，应该识别。这一普通情形可闭合。 |
+| `<!-- note \` --> <!-- verify:ignore --> \`tail\` and \`no/such.py\`` | **不能** | 当前 `CODE_SPAN = re.compile(r"`([^`]+)`")` 先扫时，第一个 match 是 `' --> <!-- verify:ignore --> '`，会把真实 marker 错遮成 code span；按 Markdown 的 HTML-comment 优先级解析则该 marker 在注释外，应被识别。实测：`marker inside first code-span match=True`。 |
+| 多行 `<!--\nverify:ignore\n-->\n\`no/such.py\`` | **不能** | “HTML 注释文法”允许跨行 token，其内容 `strip()` 后等于 marker；“一行是否携带标记”又暗示逐物理行扫描。两种实现分别会识别/不识别，且识别时 marker 行和目标行也未定义。 |
+| `<!-- broken <!-- verify:ignore --> \`no/such.py\`` | **不能** | 非贪婪 regex 得到唯一内容 `' broken <!-- verify:ignore '`，不识别；搜索内层精确注释的容错实现会识别。未规定 malformed comment 是普通文本、marker，还是违规。 |
+| `<!-- verify:ignore --><!-- rationale -->` | **不能** | 若 §3.1b“去掉注释 token”指去掉全部 comment tokens，则该行独占、目标是下一行；若只去掉命中的 marker token，则 `<!-- rationale -->` 是剩余内容、该行变成行内并对自身报 stale。 |
+| `<!-- note --> <!-- verify:ignore --> \`no/such.py\`` | 可以 | 多 token 中只要一个 token 的内容精确等于 `verify:ignore`，§3.1 第 3 步足以认定该行携带 marker。 |
+
+具体探针：
+
+```text
+line= <!-- note ` --> <!-- verify:ignore --> `tail` and `no/such.py`
+CODE_SPAN matches= [' --> <!-- verify:ignore --> ', ' and ']
+marker inside first code-span match= True
+```
+
+这主要产生漏认 marker 的 fail-closed 红灯，但它仍会让同一规格产生不兼容实现。应明确只支持单行 comment、malformed 一律不识别（或报固定 kind）、去掉的是全部还是仅 marker token，并给 comment/code-span 冲突规定真正的词法优先级。
